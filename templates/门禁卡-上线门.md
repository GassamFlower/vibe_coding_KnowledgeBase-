# 门禁卡：上线门

> 包含阶段：上线前总验收 + 上线 + Skill 反哺  
> 过门禁标准：验收过了，Skill 反哺了

---

## 过门禁标准（必须满足的指标）

- [ ] 5 维度审查完成，无 🔴 严重项
- [ ] 🟡 风险项已登记后期清单
- [ ] 上线检查清单逐项完成（构建 / 环境变量 / 迁移 / 域名 / HTTPS / 冒烟 / 监控 / 回滚）
- [ ] 生产环境冒烟测试通过，关键路径真实执行过
- [ ] 监控与告警已配置，回滚步骤已实际演练
- [ ] SEO 基础项与分享卡片已完成（对外站点）
- [ ] 访问统计已接入，关键事件已记录
- [ ] 隐私政策 / 用户协议 / 备案等合规项已确认
- [ ] 上线后 24 小时、7 天、30 天指标已记录
- [ ] 上线前验收报告已写入文件
- [ ] 项目已上线
- [ ] 复盘报告已写入文件
- [ ] 至少反哺 1 条新经验到 Skill 库
- [ ] 已 Git 提交

## 验收清单

### 上线前总验收
- [ ] 结构：目录放置 / 分层 / 重复实现
- [ ] 规则：宪法 / 真源文档 / 框架规范是否被违反
- [ ] 安全：输入校验 / 越权 / 密码 / 注入 / 过度防御
- [ ] 数据：schema / 范式 / 敏感数据 / 软删除
- [ ] 可维护性：命名 / 硬编码 / 提前封装 / 日志 / 错误 / 测试
- [ ] 无硬编码（配置 / URL / 密钥 / 错误信息）
- [ ] 无 TODO / FIXME 未处理
- [ ] 无墓碑代码残留（临时测试 / 调试打印 / 临时测试接口 / 硬编码假数据 / 一次性脚本），删除前已列清单经用户确认
- [ ] 正式回归测试与有意保留的运行日志未被误删
- [ ] 环境变量都从配置读

### 上线准备
- [ ] 生产构建成功，构建产物中不含开发调试配置
- [ ] 环境变量与密钥已在生产环境配置，未写入代码或仓库
- [ ] 数据库迁移在生产库执行并验证结果
- [ ] 上线前已做备份，恢复步骤实际演练过
- [ ] 域名解析指向正确，HTTPS 证书有效并开启自动续期
- [ ] 静态资源缓存与压缩已配置
- [ ] 健康检查地址可以访问

### 上线执行
- [ ] 生产环境冒烟测试通过（注册 / 登录 / 核心流程 / 支付或提交 / 查询结果）
- [ ] 应用日志能查到本次请求记录
- [ ] 监控面板能看到流量、错误率、响应时间
- [ ] 告警规则已配置，并有测试告警
- [ ] 回滚步骤已实际演练，回滚后冒烟测试通过
- [ ] 发布记录已填写（版本号 / 时间 / 操作人 / 变更内容）

### SEO 与运营
- [ ] 每个页面有独立的 title 和 description
- [ ] canonical、sitemap、robots.txt 已配置
- [ ] 分享卡片（Open Graph）已配置并验证显示
- [ ] 访问统计已接入，核心事件已记录（注册 / 登录 / 下单 / 支付 / 提交）
- [ ] 隐私政策、用户协议已发布（涉及用户数据或支付时必须有）
- [ ] 备案信息已展示（境内服务器站点）

### 上线后观察
- [ ] 24 小时指标已记录（访问量 / 错误率 / 响应时间 / 核心转化）
- [ ] 7 天指标已记录并与基线对比
- [ ] 30 天指标已记录并完成复盘
- [ ] 用户反馈入口可用，反馈已登记
- [ ] 30 天迭代计划已建立（`templates/上线后30天迭代计划.md`）

### Skill 反哺
- [ ] 踩坑清单已整理
- [ ] 至少 1 条新经验反哺到 Skill 库
- [ ] 复盘报告已写入文件
- [ ] 下次项目提醒已记录

## 常用 Prompt（7 个）

### 1. 上线前总验收（验收型）
```
当前阶段：上线前总验收。本轮不改代码，只审查。
你的角色：代码审查员 + 上线把关人。

请对整个项目做 5 维度审查：
1. 结构：目录放置、分层、重复实现
2. 规则：宪法、真源文档、框架规范
3. 安全：输入校验、越权、密码、注入、过度防御
4. 数据：schema、范式、敏感数据、软删除
5. 可维护性：命名、硬编码、提前封装、日志/错误/测试

每项给"通过 / 风险 / 严重"判断 + 证据（文件 + 行号）。

风险分级：
🔴 严重：阻断上线
🟡 风险：建议修，可上线后修
🟢 建议：可选优化

输出整改清单。
```

### 2. 上线决策（验收型）
```
基于审查结果，请给出上线决策：
1. 总体评估：go / no-go / conditional go
2. 🔴 严重项清单（必须修完才能上线）
3. 🟡 风险项清单（可上线后修）
4. 🟢 建议项清单（可选优化）
5. 上线前必做动作
6. 上线后观察清单

给明确判断，不要"建议视情况而定"。
```

### 3. Skill 反哺（挖掘型）
```
当前阶段：项目上线 + Skill 反哺。
你的角色：项目复盘员。

请回顾本次项目：
1. 踩了哪些坑？（列具体场景 + 根因）
2. 哪些坑是现有 Skill / Prompt 没覆盖的？
3. 哪些 Skill 的规则需要强化或补充？
4. 下个项目开始前，应该更新哪些文档？

给具体建议：改哪个 Skill 文件、加哪条规则。不要泛泛而谈。
```

### 4. 墓碑代码清理（验收型）
```
请在当前项目里全局排查一遍，有没有遗留的：
临时测试代码、调试打印、临时测试接口、假数据或一次性脚本。
请按文件列出，说明用途，给出删还是留的建议。
先把清单发给我，等我确认后再删除。

特别标出两类安全风险：
1. 没有权限校验的临时测试接口（可能被外部直接调用）
2. 硬编码的测试数据（一旦跟着上线会和真实数据混进同一个库）

另外有两样别误删：
1. 正式的回归测试——要长期保留、以后每次改动都要重跑的那套
2. 我有意留在关键功能上用于排查问题的运行日志，别当调试打印清掉
```

### 5. 部署上线与冒烟测试（执行型）
```
当前阶段：部署上线。按上线检查清单逐项执行，不要跳步。
你的角色：运维负责人。

请先确认部署方式（托管平台 / 自有服务器），然后按顺序执行：
1. 生产构建：给出构建命令和构建结果
2. 环境变量：列出生产环境需要的全部变量，确认已配置，确认没有写入代码或仓库
3. 数据库迁移：给出迁移命令、执行结果、迁移后的表结构验证
4. 备份：执行备份命令，确认备份文件存在
5. 发布：给出发布命令和发布结果
6. 域名与证书：验证解析、HTTPS、证书有效期
7. 冒烟测试：按核心用户流程实际走一遍，给出每步请求和响应
8. 日志与监控：确认日志能查到本次请求，监控面板有数据
9. 回滚演练：实际执行一次回滚，回滚后再次冒烟测试，确认可用

每步给：命令 + 输出 + 是否通过。未执行的步骤标记"未执行"。
不要用"应该可以"代替实际执行。
```

### 6. SEO、统计与合规检查（验收型）
```
当前阶段：上线前 SEO 与合规检查。
你的角色：增长与合规检查员。

请逐项检查并给出证据：
1. 每个页面的 title 和 description 是否独立、是否包含核心关键词
2. canonical 是否正确，sitemap 和 robots.txt 是否可访问
3. 分享卡片是否配置，实际抓取后显示的标题、描述、图片是否正确
4. 访问统计脚本是否已加载，核心事件是否真的能记录到
5. 隐私政策和用户协议是否覆盖实际收集的数据和使用的第三方服务
6. 境内服务器是否完成备案并在页面展示备案号
7. 是否存在收集了但未在隐私政策中说明的数据

每项给：检查方式 + 实际结果 + 是否通过 + 需要补的内容。
```

### 7. 上线后 30 天迭代（挖掘型）
```
当前阶段：上线后运营。项目已经上线，本轮做数据观察和迭代决策。
你的角色：产品负责人。

请建立上线后的观察与迭代机制：
1. 指标基线：列出 5 个核心指标（访问 / 注册 / 激活 / 付费或核心动作 / 留存），给出当前数值
2. 反馈收集：列出反馈渠道，把已有反馈逐条登记（来源 / 原话 / 场景 / 情绪）
3. 反馈归类：按缺陷、体验、功能缺失、误解、价格五类分组
4. 优先级：用 RICE 对候选需求排序（覆盖人数 / 影响程度 / 信心 / 工作量）
5. 本周假设：选出 1 个最值得验证的假设，写清验证方式和成功标准
6. 发布节奏：确定本周改什么、怎么灰度、什么条件下回退

输出一份 30 天迭代计划（可套用 templates/上线后30天迭代计划.md）。
不要一次列 20 个需求，只保留本周能验证的 1-3 个。
```

## 常见遗漏项

- ⚠️ 跳过总验收直接上线
- ⚠️ 🔴 严重项没修完就上线
- ⚠️ **生产环境没做冒烟测试**（本地能跑就认为线上能跑）
- ⚠️ 环境变量和密钥写进代码，或打包进前端产物
- ⚠️ 数据库迁移只在本地跑过，生产没执行或执行失败
- ⚠️ 没有备份就开始迁移
- ⚠️ 域名解析或证书过期，上线后打不开
- ⚠️ **没有回滚方案，或回滚方案从未演练**（出问题只能干等）
- ⚠️ 没有监控和告警，服务挂了靠用户通知
- ⚠️ 日志里查不到请求，出问题无法定位
- ⚠️ 页面没有独立 title 和 description，分享出去是一串链接
- ⚠️ 统计脚本接入了但关键事件没记录，上线后无法判断效果
- ⚠️ 收集了用户数据却没有隐私政策，或隐私政策与实际收集不符
- ⚠️ 境内服务器没有备案
- ⚠️ 上线完就结束，Skill 没迭代
- ⚠️ 反哺只写"以后注意"（要写具体规则）
- ⚠️ 不记录下次项目提醒
- ⚠️ 审查不给证据
- ⚠️ 顺手重构审查范围外代码
- ⚠️ 墓碑代码没清就上线（临时接口无权限校验 / 假数据进库是安全风险）
- ⚠️ 不列清单确认就直接删代码（或误删正式回归测试 / 运行日志）
