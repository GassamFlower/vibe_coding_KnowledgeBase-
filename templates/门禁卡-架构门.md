> 包含阶段：实施真源文档分解 + 前端骨架 + 数据库设计 + 后端骨架 + 后端联调 + 后端验收

## 验收清单

### 实施真源文档分解
- [ ] 首个大阶段已分解（大阶段 → 子阶段 → 步骤）
- [ ] 每步有验收标准
- [ ] 没有一性次分解完所有阶段（完成一个分解一个）
- [ ] 临时想法写回真源文档，不是直接改代码

### 前端骨架
- [ ] 设计风格已明确，用一句话写清方向
- [ ] 设计 token 已定义（颜色 / 字号 / 间距 / 圆角 / 阴影 / 断点）
- [ ] 页面只使用 token，不直接写十六进制颜色和随手取的字号
- [ ] UI 组件库已接入，只选一个主组件库
- [ ] 响应式断点和内容最大宽度已明确
- [ ] 加载、空、错误、禁用、成功状态已覆盖
- [ ] 键盘聚焦、对比度、语义标签等可访问性底线已检查
- [ ] 目录结构符合规范
- [ ] 路由结构搭好
- [ ] 接口层封装完成
- [ ] 项目能启动、首页能打开

设计规范起点可对照本机 UIUX 参考库：`DESIGN_SYSTEM.md` §1–§8、§10、§11（设计原则 / token / 组件 / 页面状态 / 响应式 / 无障碍 / AI 规则）、`projects.html`（组件库选型）、`patterns.html`（页面套路），入口见知识库 `references/UIUX参考库索引.md`。

### 数据库设计
- [ ] 业务对象清单已整理
- [ ] 对象关系已确认（ER 图）
- [ ] 表结构符合三大范式（或反范式有说明）
- [ ] 金额用 decimal、密码哈希存储、软删除字段一致
- [ ] schema.sql 或 migration 已生成且可独立执行
- [ ] 索引清单与对应查询已说明
- [ ] 事务边界已说明
- [ ] 连接池上限、超时、空闲回收已配置
- [ ] 需要数据隔离的表有租户或用户条件，必要时配置行级权限
- [ ] 备份频率、保留时间、恢复步骤已说明
- [ ] 数据库能连接、能建表、能插入查询测试数据

### 后端骨架
- [ ] 基于架构设计文档搭骨架
- [ ] 接口清单已写入文件，前后端使用同一份
- [ ] 统一响应结构和错误码表已写入文件
- [ ] 列表接口有分页和上限，排序使用白名单
- [ ] 关键写操作有幂等方案
- [ ] 4 条线跑通（启动 / 接口 / 业务 / 运维）
- [ ] 配置 / 环境变量规范处理
- [ ] `.env.example` 列出全部变量名和说明
- [ ] README 写清依赖安装、启动、构建、测试、迁移命令
- [ ] 健康检查接口可以访问

### 后端联调
- [ ] 前端能调通后端示例接口
- [ ] 跨域配置正确
- [ ] 响应格式前后端一致
- [ ] 错误场景验证通过

### 后端验收
- [ ] 9 项验收每项有证据（文件 / 命令 / 输出 / 日志）
- [ ] 无"基本完成"等模糊词
- [ ] 《后端架构实施真源文档》已写入文件
- [ ] Agent 宪法已加引用条款

## 常用 Prompt（6 个）

### 1. 实施真源文档分解（挖掘型）
```
请先把首个大阶段分解成实施真源文档：
1. 大阶段名称和目标
2. 子阶段划分（每个子阶段的目标）
3. 每个子阶段的步骤（每步做什么）
4. 每步的验收标准（怎么算做完）

三大核心：明确执行目标、划定任务边界、制定验收标准。
先只分解首个阶段，后续完成后再分解下一个。
```

### 2. 前端骨架搭建（执行型）
```
现在按文档搭骨架。本轮范围限定：
- 项目能启动
- 首页能打开
- 设计 token 已定义并生效
- UI 组件库已接入
- 目录结构按文档创建
- 路由结构搭好
- 接口层封装好

不要写业务页面。不要一次性做完所有功能。
完成后按验收清单自检，每项给证据。
```

### 3. 数据库设计（挖掘型）
```
当前阶段：数据库设计。先出设计文件，确认后再建表。
你的角色：数据库架构师。

请按以下顺序推进，每步等我确认再进下一步：
第 1 步：业务对象清单 + 关系图（Mermaid ER 图）
第 2 步：核心表设计（字段 / 类型 / 约束 / 索引）
第 3 步：三大范式校验
第 4 步：生成 schema.sql

每步给完让我 review，确认后再进下一步。
```

### 4. 后端联调（执行型）
```
当前阶段：后端联调。验证前后端骨架是否接得上。
请完成前后端联调验证：
1. 前端调用后端示例接口（健康检查），返回正常
2. 跨域配置正确
3. 响应格式前后端一致
4. 错误场景验证
5. 网络/超时场景验证

每项给：请求命令 + 响应输出 + 是否通过。
不要写业务功能。只验证骨架联调。
```

### 5. 后端验收（验收型）
```
当前阶段：后端架构验收。本轮不改代码，只验收。
你的角色：后端架构审查员。

请按 9 项验收清单逐项检查，每项必须给证据（文件 / 命令 / 输出 / 日志）。
未验证项标记"未验证"。禁止使用"基本完成""应该没问题"。

每项给：规则来源 + 实际证据 + 是否通过。
```

### 6. 接口清单设计（挖掘型）
```
当前阶段：接口清单设计。先出清单文件，确认后再写接口代码。
你的角色：接口设计负责人。

请依据立项文档和数据库设计输出接口清单，按以下顺序推进：
1. 资源划分：列出业务对象，确定每个对象的接口归属
2. 接口列表：每个接口写清路径、方法、用途、调用方、权限要求
3. 入参出参：字段名、类型、是否必填、取值范围、示例
4. 错误场景：每个接口可能出现的错误和对应错误码
5. 列表规则：分页参数、默认条数、最大条数、排序字段白名单、筛选条件
6. 写操作规则：哪些接口需要幂等，采用什么方案，重复提交会返回什么
7. 权限矩阵：角色 × 接口，标清可访问、不可访问、仅限本人数据

输出一份接口清单文件（可套用 templates/API接口清单模板.md），前后端共用这一份。
先给资源划分和接口列表，等我确认再补细节。不要写接口代码。
```

## 常见遗漏项

- ⚠️ **跳过实施真源文档分解直接写代码**（没有实施依据，AI 自由发挥）
- ⚠️ **一次性分解完所有阶段**（应该完成一个分解一个，避免后续大幅修改）
- ⚠️ 设计 token 没定就开始写页面
- ⚠️ 页面直接写十六进制颜色和随手取的字号（token 形同虚设）
- ⚠️ 只做正常状态，加载、空、错误、禁用状态全部缺失
- ⚠️ **接口清单前后端各写一份**（字段和错误码对不上，联调时互相猜）
- ⚠️ 列表接口没有条数上限，排序字段直接拼进 SQL（性能和数据泄露风险）
- ⚠️ 写操作没有幂等方案，重复提交产生重复订单或重复扣款
- ⚠️ 直接连数据库建表（必须先出 schema.sql）
- ⚠️ 金额用 float（必须用 decimal）
- ⚠️ 密码明文存储
- ⚠️ 建了表没写索引，等数据变多才发现查询慢
- ⚠️ 多表写入没有事务边界说明
- ⚠️ 后端骨架不基于架构设计文档
- ⚠️ **跳过后端联调直接写业务**（接口接不上再查更难）
- ⚠️ 4 条线没跑通就宣布完成
- ⚠️ `.env.example` 缺失，换一台机器起不来
- ⚠️ README 没写依赖安装、启动、构建、测试、迁移命令
- ⚠️ 没有健康检查接口，部署后无法判断服务是否活着
- ⚠️ 验收不给证据，只说"已完成"
- ⚠️ 真源文档写设计意图不写实际实现
- ⚠️ 改了规则没同步真源文档
