# 门禁卡：业务门

> 包含阶段：业务模块开发（多轮）+ 安全审查  
> 过门禁标准：功能做完了，安全过了

---

## 过门禁标准（必须满足的指标）

- [ ] 所有 P0 功能已开发完成
- [ ] 每轮开发都有验收证据
- [ ] 每个模块走过测试六步法（`testing-strategy` Skill）
- [ ] 核心接口有自动化测试，核心流程有 E2E 验证
- [ ] 安全审查 5 道关卡全过
- [ ] 水平越权测试通过
- [ ] 无字符串拼接用户输入
- [ ] 认证与密钥管理检查通过
- [ ] 跨域白名单、角色权限、限流三项已配置
- [ ] 依赖审计无已知高危漏洞
- [ ] 安全审查报告已写入文件
- [ ] 已 Git 提交

---

## 验收清单

### 业务模块开发（每轮）
- [ ] 本轮范围限定（只做计划内的任务）
- [ ] 功能：核心路径走通（给执行命令和输出）
- [ ] 规则：无违反宪法 / 真源文档
- [ ] 安全：接口输入后端重新校验、权限校验到位、敏感数据哈希
- [ ] 数据：结构变更先改 schema
- [ ] 接口：返回示例覆盖成功 / 失败 / 边界
- [ ] 测试：核心接口有自动化测试，覆盖成功、参数错误、未登录、无权限
- [ ] 幂等：关键写操作重复提交验证过，不产生重复数据
- [ ] 日志：关键操作有日志
- [ ] 回归：相邻功能未被破坏
- [ ] 真源文档已同步（如有规则变更）

### 安全审查
- [ ] 身份认证：哪些接口需要登录，在哪里校验
- [ ] 权限控制：哪些接口限定角色，无权限返回什么
- [ ] 输入校验：关键参数在哪里后端重新校验
- [ ] 数据归属：水平越权测试通过（用户 A 不能访问用户 B 的资源）
- [ ] 注入防护：无字符串拼接用户输入
- [ ] 密码规则齐全（长度 + 字符组合 + 弱密码拦截 + 哈希 + 失败限制）
- [ ] 认证与密钥：token 有效期和刷新规则已定，密钥只从环境变量读取
- [ ] 密钥管理：密钥不入库、不进前端代码、不写入日志；`.env` 已加入 `.gitignore`
- [ ] 跨域：只允许明确列出的来源，凭证请求有对应配置
- [ ] 角色权限：角色 × 接口矩阵存在，管理员接口有单独校验
- [ ] 限流：登录、注册、验证码、发送类接口有频率上限
- [ ] 生产错误信息：对外只返回错误码和用户可读信息，不暴露路径、SQL、调用信息
- [ ] 依赖审计：锁定文件已提交，审计命令无已知高危漏洞
- [ ] 无过度防御 / 无用代码
- [ ] 安全审查报告已写入文件
- [ ] 整改清单全部处理
- [ ] 纯前端 / 小程序项目：改走 frontend-security-review（XSS / CSRF / 敏感信息不入 localStorage / 依赖无已知漏洞 / 构建不带 source map）

## 常用 Prompt（5 个）

### 1. 模块开发计划（挖掘型）
```
当前阶段：业务模块开发 - [模块名]

本模块要做的接口 / 页面：[列]
依赖的已完成模块：[列]

请先输出本模块实施计划：
1. 接口清单（路径 / 方法 / 入参 / 出参 / 权限 / P0-P2）
2. 页面清单（路由 / 组件 / 状态 / P0-P2）
3. 涉及的业务对象 / 表变更
4. 涉及的规则变更
5. 本轮任务划分（一个模块分 N 轮）
6. 每轮的验收标准

我确认计划后再开始写。
```

### 2. 完成前验收（验收型）
```
在说"已完成"之前，请按以下清单自检并交证据：
- 功能：核心路径走通了吗？给执行命令和输出
- 规则：有没有违反宪法 / 真源文档？
- 安全：接口输入后端重新校验了吗？权限校验在哪里？
- 数据：数据库变更先改 schema 了吗？
- 接口：返回示例覆盖成功 / 失败 / 边界了吗？
- 日志：关键操作有日志吗？
- 回归：相邻功能没被破坏吧？给证据

每项给文件 / 命令 / 输出 / 日志作为证据。
未验证项标记"未验证"。不允许写"基本完成"。
```

### 3. 安全审查（验收型）
```
当前阶段：后端安全审查。不要只说"已做安全处理"。
你的角色：安全审查员。

请按 5 道关卡分别说明：
1. 身份认证
2. 权限控制
3. 输入校验
4. 数据归属（重点查水平越权）
5. 注入防护

每道关卡给：风险 / 处理位置（文件 + 行号）/ 处理规则 / 如何验证 / 是否通过。
最后输出整改清单，按严重 / 风险 / 建议分级。
```

### 4. 接口自动化测试（执行型）
```
当前阶段：接口自动化测试。为本轮新增或修改的接口补测试。
你的角色：测试开发。

请按以下要求输出测试：
1. 每个接口至少覆盖：成功、必填缺失、类型错误、未登录、无权限、访问他人数据、资源不存在
2. 列表接口额外覆盖：空列表、分页边界、非法排序字段
3. 写接口额外覆盖：重复提交（幂等）、事务回滚、并发冲突
4. 测试使用真实数据库或测试数据库，不使用 mock 代替数据库
5. 每条测试写清：测试名称、前置数据、请求、断言、清理方式

先给测试文件清单和用例表，我确认后再写测试代码。
写完后实际运行，给出运行命令和完整结果。
```

### 5. 核心流程 E2E 验证（执行型）
```
当前阶段：核心流程端到端验证。不要只测接口，要按用户真实路径走一遍。
你的角色：测试负责人。

请列出本阶段的核心用户流程（例如注册 → 登录 → 创建 → 支付 → 查看结果），逐条验证：
1. 从哪个页面进入，点击了哪些按钮，填写了哪些内容
2. 每一步的页面反馈是否正确
3. 数据库中的最终状态是什么
4. 中途刷新、返回、重复提交会发生什么
5. 失败后能否重新操作

每步给：操作步骤 + 页面结果 + 数据库查询结果 + 是否通过。
没有实际执行的项目标记"未验证"。
```

## 常见遗漏项

- ⚠️ 一口气写完所有业务（必须分轮）
- ⚠️ 跳过每轮验收
- ⚠️ 改了规则不改真源文档
- ⚠️ 一个模块未验收就开下一个
- ⚠️ 安全只做"要不要登录"忽略水平越权
- ⚠️ 让 AI 自己写过滤规则代替参数化查询
- ⚠️ 整改时顺手改其他代码
- ⚠️ 安全审查不给证据
- ⚠️ **只测成功路径**（参数错误、未登录、无权限、访问他人数据都没测）
- ⚠️ **用 mock 代替数据库做接口测试**（测过了，上线就报错）
- ⚠️ 写接口不测重复提交，用户连点两次就产生两条记录
- ⚠️ token 没有有效期和刷新规则，退出登录后旧 token 仍可用
- ⚠️ 密钥写进代码或提交进仓库，或被打进前端构建产物
- ⚠️ 跨域配置为通配符并允许携带凭证
- ⚠️ 管理员接口只在前端隐藏入口，后端没有角色校验
- ⚠️ 登录和发送验证码接口没有频率限制
- ⚠️ 生产环境返回调用信息、SQL 或文件路径
- ⚠️ 依赖有已知高危漏洞却未处理
- ⚠️ 纯前端 / 小程序项目跳过安全审查（应改走 frontend-security-review，不是省掉）
