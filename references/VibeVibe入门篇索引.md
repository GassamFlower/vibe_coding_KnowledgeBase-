> 用途：把 vibevibe.cn「入门篇」10 个页面整理成逐章摘要，覆盖每章的核心方法、关键做法、子页要点与适用阶段。

## 怎么用

1. 第一次接触这套方法时，从第 0 章读起，再按第 1 到 6 章顺序走完一次完整闭环。
2. 「关键做法」保留原文给出的工具名、数字与判断标准。
3. 「子页」给出每节的具体动作；需要完整步骤时打开章节页，从页尾导航进入子页。
4. 附录按问题查，不按顺序读；结语与下部预告用于收束第一次闭环并选择下一步。

## 第 0 章 开始前

- 页面：<https://www.vibevibe.cn/Basic/00-preface/>
- 核心：说明基础篇的终点、适合人群与卡住时的求助方式，读者拿到六章学习地图后开始动手。
- 关键做法：
  - 最终作品是个人主页加数字分身，含首屏、内容区、聊天入口与公网发布四部分，按 v1 到 v6 迭代。
  - 三条学习路径：只看第 0 章后直接做第 1 章、按第 0 到第 6 章走完整闭环、边做边跳读。
  - 求助模板写三件事：刚刚做了什么、现在看到什么问题、原本想要什么结果，再附截图或完整报错。
  - 每章末尾按验收清单确认后再进入下一章，一次只推进一个小节。
- 子页：

| 子页 | 要点 |
|---|---|
| 0.1 这本教程在教什么，以及你会做出什么 | 定位为学开车，先做作品再按需理解概念；作品由首屏、内容区、数字分身、正式发布四部分组成，分成 v1 到 v6 六步。 |
| 0.2 谁适合学，以及怎么学最有效 | 适合零基础学生、产品运营设计、想做作品集、低成本试项目的人；想系统学完整原理或一上手做复杂 SaaS 的读者留到进阶篇。 |
| 0.3 卡住时怎么办 | 给出三段式提问模板，配页面空白、按钮无反应、回答机械三个示例；首次未解决就补充改动部位与报错原文。 |
| 0.4 本章小结：基础版学习地图 | 列出六章各自把作品推进到哪，第 1 章拿正反馈、第 6 章完成闭环；附出发前五条确认项。 |

- 适用：阶段 1 之前的入门准备 / 无门禁；`docs/使用教程与导航手册.md`

## 第 1 章 第一个版本

- 页面：<https://www.vibevibe.cn/Basic/01-awakening/>
- 核心：以秒哒为例，两小时做出能预览、能展示、能简单聊天的 v1 个人主页与数字分身，并完成三轮微调与第一次验收。
- 关键做法：
  - 生成前准备名字、头像、一句话介绍、当前在做的事、2-4 个兴趣、1 个记忆点、主要访客与别人最常问的 3 个问题。
  - 用五段填空模板：关于我、给谁看、页面至少要有、数字分身需要知道、风格要求；声明先保证结构清楚可用、不过度复杂、先出可预览版本。
  - 平台先给结构化需求文档，确认应用名称、核心功能、页面结构与风格后再生成。
  - 三轮微调分别修明显错误、调风格与配色、做小幅细化；每轮只改一类问题，并写明不新增模块。
  - 验收线：页面能打开、名字与介绍清楚、聊天入口能基础提问、手机端能浏览；遗留问题按界面、内容、数字分身、体验四类记清单。
- 子页：

| 子页 | 要点 |
|---|---|
| 1.1 为什么从这一章开始，以及先准备什么 | 先拿第一次正反馈；素材要具体，例如把「我是一个有热情的人」改成「我最近在整理自己的作品」。 |
| 1.2 用填空式模板写出第一版需求 | 给出五段模板与填好示例（林安、内容策划、深蓝与白、适配手机）；模板用于补上下文、收范围、定优先级。 |
| 1.3 在平台里生成第一个版本并完成三轮微调 | 新建 my-homepage 或「个人主页-v1」项目，整段粘贴后等生成完成再预览；首轮只看结构、个人信息、聊天区三件事。 |
| 1.4 本章小结：第一轮验收与下一轮优化清单 | 五条验收清单覆盖能打开、介绍清楚、像个人主页、聊天入口可用、手机端可浏览；四类清单标注优先级与对应章节。 |

- 适用：阶段 1 立项 / 立项门；product-validation、brainstorming

## 第 2 章 带回自己的工作台

- 页面：<https://www.vibevibe.cn/Basic/02-mindset/>
- 核心：把平台里的 v1 导出到本地固定目录，用 AI IDE 打开并运行，完成一次最小修改，从此拥有可持续修改的项目。
- 关键做法：
  - 导出入口可能叫导出代码、下载项目或同步代码；确认拿到当前可用版本，解压后改成看得懂的名字，放进固定目录。
  - 命名用 my-homepage、digital-twin-site、linan-homepage 一类；避开新建文件夹、项目最终版2、个人主页最新最终不改了。
  - 打开顺序：AI IDE 打开文件夹 → 让 AI 判断项目类型与启动方式 → 安装依赖并运行 → 浏览器打开本地地址确认。
  - 报错时把终端输出原样贴给 AI，要求先判断最可能的原因，再只给下一步动作。
  - 只认三类位置：页面入口、聊天相关代码、样式或配置；最小修改先改一句文案。
- 子页：

| 子页 | 要点 |
|---|---|
| 2.1 为什么要把项目带回本地，以及如何把它导出下来 | 本地解决固定位置、长期可改、文件可见、更可控四件事；导出四步为确认版本、解压、改文件夹名、放入固定目录。 |
| 2.2 用 AI IDE 打开它，并先认识最关键的几部分 | 只选一个手边顺手的 IDE，Cursor、Trae、Claude Code 任选其一；让 AI 用人话讲主页入口、聊天区代码与样式文件位置。 |
| 2.3 完成一次最小修改，并学会 3 类高频提问 | 先改一句介绍或按钮文案，走通提出修改、AI 改动、页面变化、我确认；理解类、定位类、约束类三种提问各有用处。 |
| 2.4 本章小结：你的本地工作台已经搭好 | 四条验收清单：项目有固定位置、能用 AI IDE 打开并运行、知道关键文件大概位置、完成过至少一次本地修改。 |

- 适用：阶段 2 技术选型 / 立项门；writing-plans

## 第 3 章 做好第一印象

- 页面：<https://www.vibevibe.cn/Basic/03-technique/>
- 核心：把更简洁、更有层次、更像我这类感觉转成 AI 能执行的修改方向，做出有主次、手机端可读、聊天入口显眼的首页。
- 关键做法：
  - 改前先定一个方向：简约专业、温暖友好、轻微科技感，只求统一。
  - 只动三处：首屏排版、颜色与字体、区块层次与留白；主色只保留 1 个。
  - 改界面说三层：现在的问题、想改成的感觉、这次动哪些与不动哪些。
  - 可附截图、参考网站或一句风格描述，并要求兼顾首屏识别、聊天入口明显、手机端文字可读。
- 子页：

| 子页 | 要点 |
|---|---|
| 3.1 为什么先改界面，以及先选一个清晰的风格方向 | 界面反馈最快，改完立刻能判断；三种方向里选一个立住，避免几种风格同时并存。 |
| 3.2 三个最值回票价的界面改动 | 首屏看名字与一句话介绍是否显眼、头像是否抢信息、主按钮是否清楚、数字分身入口存在感；区块之间留出呼吸感。 |
| 3.3 用更清晰的话告诉 AI 你想怎么改，并兼顾好不好用 | 用三层句式加参考物；顺手提体验要求：首屏一眼看出我是谁、聊天入口更明显、手机端可读、按钮有基本反馈。 |
| 3.4 本章小结：你的首页已经像一个作品 | 验收：首页不再像默认模板、别人更快知道你是谁、聊天入口更明显、能说清问题、目标感觉与修改边界。 |

- 适用：阶段 6 前端骨架 / 架构门；ui-design-system

## 第 4 章 让主页更完整

- 页面：<https://www.vibevibe.cn/Basic/04-practice-0-to-1/>
- 核心：从访客视角补 2 至 3 个最有价值的模块，让数字分身入口真正被用起来；同时先建 Git 最小闭环作为回退手段。
- 关键做法：
  - Git 只记三个动作：存一次、看历史、退回来；命令可以让 AI 带着做。
  - 用「如果别人只花 30 秒看我的主页，他最该记住什么」筛选内容。
  - 朋友、HR、潜在合作伙伴三类访客取交集：你是谁、做过什么、最近在做什么、怎么联系。
  - 模块从作品展示、联系方式、经历时间线、FAQ 中选 2 到 3 个；每加一类前先存档。
  - 聊天区补提示文案、快捷问题按钮与入口说明。
- 子页：

| 子页 | 要点 |
|---|---|
| 4.1 为什么先学存档，以及 Git 的最小闭环 | 三个动作是存一次、看历史、退回来；可以直接说「请先帮我做一个最小存档，之后改坏了能退回来」。 |
| 4.2 从访客视角决定你要补什么内容 | 用 30 秒问题筛选；朋友关心最近在做什么，HR 关心做过什么与能力，合作伙伴关心擅长什么与怎么联系。 |
| 4.3 只添加 2-3 个最有价值的内容模块，并让数字分身更容易被使用 | 从作品区、联系方式、时间线、FAQ 中按缺口选；缺「看不懂我做过什么」先补作品区；一次只加 2 到 3 个。 |
| 4.4 本章小结：主页更完整，也更可回退 | 验收：会做最小存档与回退、内容更完整但没失控变多、访客能理解你是谁、数字分身入口更易用。 |

- 适用：阶段 11 业务模块开发 / 业务门；Git 动作适用全阶段；verification-before-completion

## 第 5 章 让数字分身更像你

- 页面：<https://www.vibevibe.cn/Basic/05-advanced/>
- 核心：把标准从更聪明转到更像你，写数字分身说明书并用真实材料校准，学会按症状排查。
- 关键做法：
  - 链路四步：访客提问 → 项目送出 → 模型结合说明书生成 → 回到页面显示；说明书即系统提示词。
  - 说明书四要素：你是谁、你知道什么、你怎么说话、你不知道时怎么办；边界写明不编造经历，不知道就明说并引导联系方式。
  - 用 1 至 3 组真实问答校准，例如你现在主要在做什么、你擅长什么。
  - 排查按症状：不回复查链路与配置，回答不切题查说明书与上下文，风格不对补真实样本，编造信息强化未知就收住。
  - 一次只改一层；成本上选默认够用的模型、控制回复长度；API Key 不写进代码仓库。
- 子页：

| 子页 | 要点 |
|---|---|
| 5.1 为什么「像你」比「更聪明」更重要，以及先用一句人话理解背后发生了什么 | 用一句人话理解链路四步；说明书即系统提示词，后面所有动作都是不断修订与校准这份文档。 |
| 5.2 写第一版「数字分身说明书」，并用 1-3 组真实材料校准它 | 骨架含任务、关于我、说话方式、边界；配 2 组示例问答，重点是真实，数量不必多。 |
| 5.3 四类最常见问题，以及成本与安全的最小意识 | 症状表对应查法；底线是密钥不要直接写进代码仓库，第 6 章上线前再查一次。 |
| 5.4 本章小结：它已经能更稳地代表你 | 验收四条：回答更像你、说明书说清知道与不知道、会查四类问题、知道 API Key 与环境变量要求。 |

- 适用：阶段 8 后端骨架 / 架构门；backend-security-review

## 第 6 章 正式上线

- 页面：<https://www.vibevibe.cn/Basic/06-launch/>
- 核心：把本地项目变成公网可访问的作品：推到远程仓库、经部署平台上线、上线后自测并收第一轮外部反馈。
- 关键做法：
  - 上线前五项自查：页面能打开无报错、手机端不错位、数字分身能回复、名字与作品与联系方式已补全、API Key 在环境变量里且未提交仓库。
  - 最小发布路径：本地项目 → 远程仓库（GitHub 或 Gitee）→ EdgeOne Pages → 公网链接；首次部署用默认构建配置。
  - 部署失败先取整段构建日志贴给 AI，要求只给下一步要改的一项。
  - 链接出来后自测五项；再发给 2 至 3 人，只问第一眼觉得我是做什么的、知不知道该点哪里、哪里卡住或不自然。
- 子页：

| 子页 | 要点 |
|---|---|
| 6.1 为什么把「上线」放在最后，以及上线前检查 | 第 1 章版本只是原型，等页面、内容、分身成形再公开；给出五项自查清单。 |
| 6.2 把代码推到远程仓库，并用 EdgeOne Pages 完成部署 | 记住本地项目、远程仓库、部署平台、公网链接四段路径，首次只求跑通；失败时先看日志再问 AI。 |
| 6.3 上线后自测，并收集第一轮真实反馈 | 真实环境才会暴露样式错位、环境变量漏配；自测五项，找 2 至 3 人问三问。 |
| 6.4 基础版收束：你已经从「有想法」走到了「有作品」 | 回顾六章脉络，附四条验收清单：完成闭环、有真实链接、知道下一步、知道可选路径。 |

- 适用：阶段 14 上线 / 上线门；deployment-and-ops

## 结语

- 页面：<https://www.vibevibe.cn/Basic/100-epilogue/>
- 核心：把六章闭环沉淀为可迁移动作：收素材、说清需求、拉出第一版、与 AI 迭代、带回本地、发布收反馈。
- 关键做法：
  - 先做最小可用版本，不把全部想法一次塞进去。
  - 先说清问题，再使用工具。
  - 不把报错与不完美看成失败，项目按版本逐步长出来。
  - 不退回观众位置，继续动手做下一个作品。
- 适用：阶段 14 后 / 上线门；user-feedback-iteration
