## 1 开源 AI 画布：从想法到上线

- 原文：<https://www.vibevibe.cn/Practice/ai-canvas-vibecoding-journey.html>
- 项目：把科研配图提示词做成可反复使用的画布工作流；纯前端实现，已开源并提供在线体验。
- 核心：一次交付复杂功能会让逻辑失控；先把需求写成按版本分开的开发文档，再按模块逐步交给 AI，每一步都能检查与回退。
- 要点：
  - 起初沿用做小项目时一步到位的习惯，让 AI 一次实现全部功能，结果逻辑混乱，折腾到凌晨也没有收敛。
  - 调整后的做法是先让 Gemini 3 把需求整理成详尽的分步开发文档与对应提示词，再按版本喂回，一次只做一个模块：界面布局、图片上传、提示词管理。
  - 分步与版本记录让单个功能是否完成一目了然；出问题时影响范围小，回退代价低。
  - Gemini 的接口与 OpenAI 格式不同：地址中包含模型名，官方与中转服务商的返回格式也有差异，生图结果是 base64；按服务商给出的请求示例做成兼容方案。
  - 选择纯前端 HTML 的理由是即开即用、部署简单，也让没有本地算力的学生直接用 API。
- 适用：阶段 5 实施真源文档 / 阶段 6 前端骨架 / 阶段 8 后端骨架 / 阶段 14 上线；writing-plans、api-design、systematic-debugging

## 2 AI 绘本生成器：零基础两周完成

- 原文：<https://www.vibevibe.cn/Practice/ai-picture-book-generator.html>
- 项目：把 PDF、Word、TXT 文档自动转换成儿童绘本，包含大纲、角色参考图、每页插图、PPT 导出与动画；面向无编程基础的人，约 2 周完成。
- 核心：把「文档变绘本」分解成解析、大纲、角色、插图、导出五步流水线，每一步只做一件事，并用结构化 Prompt 与角色参考图保持全书一致。
- 要点：
  - 学习路线分四段：5 分钟跑通 Demo；1-2 天完成完整项目；持续优化实际问题；最后理解原理并迁移。
  - Demo 用 Cursor 或 Windsurf，说明使用 Python 与 Gradio，接入 Nano Banana Pro 图片接口，密钥放 `.env`，异步结果通过轮询获取。
  - 文档解析接入 MinerU，支持 PDF、Word、TXT，每天 1 万次免费调用；大纲 Prompt 要求每页包含叙事目标、关键内容、视觉画面、布局四项，并禁止「不仅仅是 X，而是 Y」一类句式。
  - 角色一致性先生成包含多角度与多表情的角色设定图，每页生成时把设定图作为参考，并在 Prompt 中明确只能改变姿势、表情与场景互动。
  - 长任务用 SSE 推送进度，每生成一张图立即显示；用户照片与插画分层融合，分为真实照片层、插画层与光影融合层。
  - 常见问题：密钥写进代码上传后被盗刷 500 元；风格每页漂移；Prompt 过长时前面的要求被遗忘；生成数分钟没有反馈被当成无响应。
  - 代码按界面层、服务层、AI 层、数据层分开，更换模型只改 AI 层；外部服务包括 MinerU、Qwen、Gemini、联网搜索与图片生成。
- 适用：阶段 1 立项 / 阶段 5 实施真源文档 / 阶段 6 前端骨架 / 阶段 8 后端骨架 / 阶段 11 业务模块开发 / 阶段 12 安全审查 / 阶段 14 上线；product-validation、writing-plans、ui-design-system、api-design、backend-security-review、deployment-and-ops

## 3 AI 简历优化 SaaS：从市场验证到流式接口

- 原文：<https://www.vibevibe.cn/Practice/ai-resume-saas.html>
- 项目：根据职位描述优化简历并给出匹配评分的 SaaS，约 1 周完成，使用 Next.js 与 Kimi K2。
- 核心：先用市场数据与用户任务确认付费需求，MVP 只做简历文本与职位描述的对照优化，Prompt 验证通过后再搭界面与流式接口。
- 要点：
  - 市场依据：2024 年简历构建工具约 16 亿美元，预计 2032 年达到 31 亿美元；Rezi 有 330 万用户，年收入估计超过 240 万美元；Teal 融资 2070 万美元，用户超过 200 万，节省 40% 投递时间；招聘系统会自动过滤约 75% 的简历。
  - MVP 只有三步：左侧粘贴简历文本，右侧粘贴职位描述，中间按钮生成优化建议；明确不做文件解析与拖拽编辑器，先验证价值。
  - Prompt 采用角色、上下文、任务、要求、输出格式五段结构，要求 STAR 法则、关键词植入、量化成果，返回包含评分、缺失关键词、分析与优化文本的 JSON。
  - Kimi K2 的长上下文可用于放入目标公司的产品文档、博客与技术白皮书，让修改后的经历更符合该公司的需要。
  - 界面使用 Next.js 14 App Router、Shadcn UI、Tailwind CSS 与 Vercel AI SDK；Moonshot 接口兼容 OpenAI 规范，用 `streamText` 实现打字机效果。
  - 先给评分再给全文，例如「当前 45 分，缺少 3 个关键关键词」，让用户马上看到差距；随后记录最常复制的建议、流失步骤与截断情况。
  - 隐私处理要求先脱敏手机号与邮箱；幻觉约束写明不得编造经历；Markdown 用 react-markdown 与排版插件渲染；部署到 Vercel 后在控制台补环境变量并重新部署。
- 适用：阶段 1 立项 / 阶段 3 架构设计 / 阶段 5 实施真源文档 / 阶段 8 后端骨架 / 阶段 11 业务模块开发 / 阶段 12 安全审查 / 阶段 14 上线；product-validation、writing-plans、api-design、backend-security-review、deployment-and-ops、user-feedback-iteration

## 4 21 天思考习惯小游戏：从想法到上线

- 原文：<https://www.vibevibe.cn/Practice/full-stack-21-day-thinking-habit-game.html>
- 项目：「问题呕吐机」21 天打卡小游戏，每天随机出一个问题，用户写下思考，完成后解锁机器人记忆碎片，坚持 21 天获得完整故事。
- 核心：按产品、界面、后端、部署四个角色推进，每个阶段先产出文档或设计稿，再让 AI 按文档执行，部署平台在开工时就确定。
- 要点：
  - 产品阶段先把目的、形式与核心玩法讲清，让 AI 评估不足、检查逻辑漏洞，再让 AI 生成 10 个产品问题；能回答就说明 MVP 合格，随后按 PRD 模板整理成文档。
  - 界面阶段把 PRD 交给 AI 生成适配 Stitch 的提示词，先生成 UI 初稿，再进 Google AI Studio 调整跳转与按钮等交互，预览满意后导入 GitHub。
  - 后端阶段使用全线上开发环境 cnb.cool，仓库设为公开，新建 `.cnb.yml` 指定 8 核与开发镜像，启动 Claude Code；AI Studio 导出的项目可能缺少 `/workspace/index.tsx` 入口，需要把入口文件拖入对话让 AI 补上。
  - 后端开发前先让 Claude Code 阅读项目并规划技术文档，确认后分步执行；每天修改后提交，保留记录；每次开发后写总结文档，并可创建一个用于检查与维护的 Skill。
  - 部署阶段提前确定平台。腾讯 EdgeOne Pages 导入 GitHub 仓库，加速区域选「全球可用区（不含中国大陆）」可免 ICP 备案，按框架填写输出目录（Vite 为 `dist`，Next.js 为 `.next`），配置环境变量后部署；免费预览地址只保留三小时，需要购买域名、添加 DNS 解析与 CNAME、配置 HTTPS 证书。
  - Vercel 免费分配域名且操作简单，但只能境外访问；文中先把项目部署到 Vercel，再在腾讯云配置国内访问。
- 适用：阶段 1 立项 / 阶段 5 实施真源文档 / 阶段 6 前端骨架 / 阶段 8 后端骨架 / 阶段 14 上线；product-validation、writing-plans、ui-design-system、api-design、deployment-and-ops

## 5 Vibe 编程经验分享：有研发能力者的协作方式

- 原文：<https://www.vibevibe.cn/Practice/vibe-coding-methodology.html>
- 项目：流媒体文件服务管理系统，覆盖摄像头拉流、转码、存储、分发，以及媒资文件的播放、下载、删除、备份与过期归档。
- 核心：有研发能力的人把 AI 放在执行层，自己保留架构决策与问题根因定位；方案先行、小步推进、文档随代码同步，避免无效调试循环。
- 要点：
  - 第一条方法「方案先行，实现为后」：每个功能实现前先让模型输出技术实现方案，由人审查与调整，再按方案写代码；生成图片同理，先写视觉描述再生成。
  - 第二条方法「小步慢走，步步为营」：把大功能分解成可独立完成的小任务，每个任务有目标、方案与步骤，完成后立即同步文档与注释，并用单元测试或功能测试验证。
  - 文档采用分形结构：根目录主文件要求功能、架构与写法变更后同步子文档；每个文件夹写三行以内架构说明与文件清单；每个代码文件开头写 input、output、pos 三行注释，并注明变更时同步更新。
  - 开发策略是自上而下设计、自底向上实现：先写全局蓝图，再完成数据模型与接口等基础模块，然后逐个功能模块推进，最后做端到端集成测试。
  - 分工明确：人负责架构决策、权限边界、技术选型、代码审查、根因分析与测试设计；AI 负责增删改查、接口文档、界面生成、字段同步与测试脚本。
  - 项目真正手写的部分约占 1%，主要是文案微调、清理无用导入与重复代码、修正模型虚构接口导致的编译错误、补充边界情况。
  - 常见问题包括虚构接口、在错误假设上反复修补、过度设计、代码卫生差与边界场景遗漏；调试时如果同一问题修改 2-3 次仍未解决，应立即停止，由人定位根因后明确告诉模型，再让它重新实现。
- 适用：阶段 3 架构设计 / 阶段 4 Agent 宪法 / 阶段 5 实施真源文档 / 阶段 11 业务模块开发；writing-plans、systematic-debugging、requesting-code-review、verification-before-completion
