# 上线门自动验收

> 基于 `../../templates/门禁卡-上线门.md` 转化的可执行评估项。
> 每项：检查什么 → 怎么检查 → 通过标准 → 证据要求。
> 智能体调用本文件，逐项收集证据并判定通过/不通过。

---

## 过门禁标准（硬指标）

### 指标 1：5 维度审查完成，无 🔴 严重项

- **检查什么**：结构 / 规则 / 安全 / 数据 / 可维护性 5 维度审查报告
- **怎么检查**：读取上线前验收报告，检查风险分级
- **通过标准**：无 🔴 严重项；🟡 风险项已登记后期清单
- **证据要求**：审查报告路径

### 指标 2：上线前验收报告已落盘

- **检查什么**：`docs/p-上线前验收报告.md` 是否存在
- **怎么检查**：读取文件
- **通过标准**：报告已落盘，含 5 维度结论 + 整改清单
- **证据要求**：文件路径

### 指标 3：项目已上线（线上冒烟通过）

- **检查什么**：线上核心流程是否跑通
- **怎么检查**：线上冒烟测试记录
- **通过标准**：核心流程跑通，观察清单已列（关键指标 / 告警阈值 / 回滚条件）
- **证据要求**：冒烟测试记录 / 线上 URL

### 指标 4：复盘报告已落盘

- **检查什么**：复盘报告（Keep / Change / Add / 踩坑清单 / 下次提醒）
- **怎么检查**：读取文件，检查每条规则标注来源
- **通过标准**：复盘报告已写，踩坑清单 + 下次提醒齐全
- **证据要求**：文件路径

### 指标 5：至少反哺 1 条新经验到 Skill 库

- **检查什么**：`skills/` 是否有新增 / 强化规则
- **怎么检查**：读取 Skill 文件 diff 或更新记录
- **通过标准**：至少 1 条新经验反哺，标注来源
- **证据要求**：Skill 文件路径 + 变更说明

### 指标 6：已 Git 提交 + 知识库 push

- **检查什么**：项目 Git 提交 + 知识库提交推送
- **怎么检查**：`git log --oneline` + 知识库 push 记录
- **通过标准**：项目已提交；知识库已 commit + push
- **证据要求**：git log 输出

---

## 自动验收流程

```
1. 智能体读取本文件的 6 项硬指标
2. 逐项检查（审查报告 + 上线记录 + 复盘报告 + Skill 库 + Git）
3. 每项收集证据：文件路径 / 命令输出
4. 生成验收报告（格式同立项门）
5. 全部通过 → 项目结束，进入健康迭代 / 收尾
6. 有未通过 → 列出整改清单，不推进状态
```

---

## 常见遗漏项（反模式检查）

- ⚠️ 跳过总验收直接上线
- ⚠️ 🔴 严重项没修完就上线
- ⚠️ 上线完就结束，Skill 没迭代
- ⚠️ 反哺只写"以后注意"（要写具体规则 + 来源）
- ⚠️ 不记录下次项目提醒
- ⚠️ 审查不给证据
- ⚠️ 顺手重构审查范围外代码

## 验收结果处理

### 全部通过

1. 更新 `PROJECT_STATUS.agent.md`：
   - `current_gate` 改为 `已上线`
   - `current_phase` 改为 `15`
   - 验收清单全部勾选 ✅

3. 提示用户：项目已上线，进入健康迭代 / 收尾，记得反哺知识库

### 有未通过项

1. 生成整改清单（每项：未通过指标 + 原因 + 整改建议）
2. 不推进状态
3. 智能体协助整改，整改后重新执行本验收流程
4. 直到全部通过才推进状态
