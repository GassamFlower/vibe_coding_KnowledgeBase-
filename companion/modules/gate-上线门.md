# 上线门自动验收

> 对照 `../../templates/门禁卡-上线门.md` 逐项收集证据并判定通过/不通过。

---

## 过门禁标准（14 项必须满足的指标）

1. **5 维度审查**：结构 / 规则 / 安全 / 数据 / 可维护性，每项给通过 / 风险 / 严重 + 证据；无 🔴 严重项。
2. **🟡 风险登记**：风险项全部登记到后期清单，有跟进方式；🟢 建议项列明。
3. **上线检查清单**：`docs/p-上线检查清单.md` 逐项完成——生产构建 / 环境变量 / 迁移 / 备份恢复 / 域名与 HTTPS / 静态资源缓存 / 健康检查。
4. **生产冒烟**：注册 / 登录 / 核心流程 / 支付或提交 / 查询结果在线上真实执行，给请求和响应。
5. **监控告警与回滚**：日志能查到本次请求，监控有流量 / 错误率 / 响应时间，告警有测试记录，回滚已实际演练且回滚后冒烟通过。
6. **SEO 与分享卡片**：每页独立 title / description，canonical / sitemap / robots.txt 已配置，Open Graph 已验证显示。
7. **统计事件**：访问统计已接入，注册 / 登录 / 下单 / 支付 / 提交等关键事件能在后台看到。
8. **合规项**：隐私政策与用户协议已发布并覆盖实际收集的数据；境内服务器已备案并展示备案号。
9. **上线后指标**：24 小时 / 7 天 / 30 天指标已记录并与基线对比，反馈已登记，`docs/r-上线后30天迭代计划.md` 已建立。
10. **上线前验收报告**：`docs/p-上线前验收报告.md` 已写入文件，总体评估明确（go / no-go / conditional go），整改清单分级完整。
11. **已上线**：生产地址可访问；发布记录含版本号 / 时间 / 操作人 / 变更内容 / 部署命令 / 回滚命令。
12. **复盘报告**：`docs/q-项目复盘报告.md` 含上线记录 / 指标基线 / 踩坑清单 / 下次项目提醒。
13. **Skill 反哺**：至少 1 条可执行规则写入 `skills/`，具体到文件与规则；写"以后注意"不算。
14. **Git 提交**：含上线、复盘、反哺相关提交。

---

## 自动验收流程

1. 逐项检查报告、线上访问、冒烟记录、监控与回滚记录、Git 历史。
2. 每项收集证据：文件路径 / 命令输出 / 截图。
3. 生成验收报告，每项标注 ✅ / ❌ + 证据或整改建议。
4. 全部通过 → 项目收官；有未通过 → 列整改清单，不推进状态。

---

## 常见遗漏项（反模式检查）

- ⚠️ 跳过总验收直接上线
- ⚠️ 🔴 严重项没修完就上线
- ⚠️ 生产环境没做冒烟测试
- ⚠️ 环境变量和密钥写进代码，或打包进前端产物
- ⚠️ 数据库迁移只在本地跑过，没有备份就开始迁移
- ⚠️ 域名解析或证书过期，上线后打不开
- ⚠️ 没有回滚方案，或回滚方案从未演练
- ⚠️ 没有监控和告警，日志里查不到请求
- ⚠️ 页面没有独立 title 和 description，分享出去是一串链接
- ⚠️ 统计接入了但关键事件没记录
- ⚠️ 收集了用户数据却没有隐私政策，境内服务器没有备案
- ⚠️ 上线完就结束，Skill 没迭代；反哺只写"以后注意"
- ⚠️ 不记录下次项目提醒
- ⚠️ 审查不给证据，顺手重构审查范围外的代码
- ⚠️ 上线后没有观察清单（关键指标 / 告警 / 回滚）
- ⚠️ 墓碑代码没清就上线，或不列清单确认就直接删代码

## 验收结果处理

### 全部通过

1. 更新 `PROJECT_STATUS.agent.md`：`current_gate` 改为 `无（已上线）`，`current_phase` 改为 `14`，`current_state` 改为 `4`，验收清单全部勾选。
2. Git 提交：`git commit -m "chore: 通过上线门，项目收官"`。
3. 提示用户：项目收官，反哺的新规则已被知识库继承。

### 有未通过项

1. 生成整改清单（未通过指标 + 原因 + 整改建议）。
2. 不推进状态（🔴 未修完不允许上线）。
3. 整改后重新执行本验收，直到全部通过才收官。
