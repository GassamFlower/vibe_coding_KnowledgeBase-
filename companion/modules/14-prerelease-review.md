# 阶段14：上线前总验收（上线门）

目标：5 维度审查，无 🔴 严重项才上线。

动作清单：
- 回顾所有门禁是否已通过（立项 / 架构 / 业务）
- 功能清单逐项核对；模块清单状态明确（可上线 / 需优化 / 阻塞中）
- 文档完整性检查（PRD / 选型 / 架构设计 / 宪法 / 真源文档 / API 接口清单 / 验收报告齐全）
- 5 维度审查：结构 / 规则 / 安全 / 数据 / 可维护性，每项给 通过/风险/严重 + 证据
- 墓碑代码清理：先列清单发用户 → 确认 → 再删；正式回归测试与有意保留的运行日志不删
- 逐项填写 `docs/p-上线检查清单.md`：生产构建 / 环境变量 / 迁移 / 备份恢复 / 域名与 HTTPS / 静态资源缓存 / 健康检查
- SEO：每页独立 title / description、canonical、sitemap、robots.txt、Open Graph 分享卡片
- 统计：访问统计已接入，注册 / 登录 / 下单 / 支付 / 提交等关键事件能记录
- 合规：隐私政策、用户协议、境内服务器备案号（按实际业务判断）
- 上线决策（go / no-go / conditional go），写入 `docs/p-上线前验收报告.md`
- 提交 Git：`git commit -m "chore: 上线前总验收通过"`

提示：没做总验收直接上线 = 线上出事没底。🔴 严重项没修完禁止上线。
