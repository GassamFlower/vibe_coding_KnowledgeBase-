# 成本与心力管理（每次会话都注意）

Vibe Coding 最大的隐性成本是 Token（上下文膨胀）和你的心力。以下规则每个阶段、每次会话都生效，生成器会把它注入到 `AGENTS.md`，IDE 里的 LLM 每次动手前都能看到。

## 上下文控制（省钱）
- 一事一议：一个独立任务开一个新会话，别在同一会话里堆不相关内容（上下文会线性甚至指数膨胀）。
- 明确忽略：读取 / 搜索时忽略 `node_modules`、`dist`、`build`、`.next`、`.git`、`logs`、`coverage` 等无关目录与产物，避免上下文污染。
- 工具输出先过滤：让 AI 只回关键证据（命令 + 关键输出行），别把整屏 `ls` / `cat` / `grep` 全量塞进上下文。
- 超长就压缩：上下文明显变长（如超过约 60 轮或大量工具输出）时，先用 `/compact` 压缩，或开新会话并贴一段进度摘要再继续。
- 会话熔断：单会话消息数 ≤ 60，到顶主动开新会话，不要硬撑。

## 心力管理（省神）
- 你是 PM 不是 coder：负责定义需求、验收成果、管理 AI，不要逐行审代码。
- 聚焦叶子节点：优先让 AI 做不被其他模块依赖的末端功能，即便有技术债也影响小。
- 可验证抽象层：用验收测试 / 真源文档做高层级验收，而非逐行读代码。
- 分层用模型：测试 / 检查用轻量模型，核心生成用付费主力，复杂审查用高端模型；留意平台隐藏 Token 与流量费。
