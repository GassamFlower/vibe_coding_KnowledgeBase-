# 阶段3：选型

目标：为立项中的问题选技术栈，且每选必给理由。

动作清单：
- 语言 / 框架 / 存储 / 部署 各列候选
- 每项给「为什么选它 / 为什么不选中选」
- 记录约束（团队熟悉度、合规、性能）
- 输出 `docs/d-选型.md`

选型维度清单（逐项过，缺一不可）：产品形态 / 部署要求 / 维护能力 / 性能规模 / 生态维护状态 / 合规要求 / 已有技术栈 / 扩展方向。

铁律：选型文档必须写「否决理由」，否则等于没选。AI 不得在选型文档缺否决理由时擅自定栈。

换栈决策（选型后触发）：先对照选型文档里的「重评估条件」判断是否真命中 → 算换栈成本（代码量 / 依赖 / 迁移 / 学习成本）→ 唯一推荐 + 否决理由 → 先改文档再改代码。禁止"听一句别的框架好"就换、禁止边换边写。
