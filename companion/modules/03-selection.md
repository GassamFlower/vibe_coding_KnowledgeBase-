# 阶段3：选型

目标：为立项中的问题选技术方案，每选必给理由。

动作清单：
- 前端框架 / 后端语言与框架 / 数据库 / SDK 各给唯一推荐
- 写明运行时版本、包管理器、数据库版本（换台机器能照着重装）
- 每项给「为什么选它 / 为什么淘汰其他方案」（至少 3 个被淘汰方案）
- 记录约束（团队熟悉度、合规、性能）
- 写清什么情况下需要重新评估
- 输出 `docs/d-选型.md`，补 `.env.example`（不含真值）和 README（安装 / 启动 / 构建命令）

选型维度清单（逐项过，缺一不可）：产品形态 / 部署要求 / 维护能力 / 性能规模 / 生态维护状态 / 合规要求 / 已有技术方案 / 扩展方向。

必须遵守：选型文档必须写「淘汰理由」，否则等于没选。AI 不得在选型文档缺淘汰理由时擅自确定方案。

更换技术方案的决策（选型后触发）：先对照选型文档里的「重新评估条件」判断是否真命中 → 算更换成本（代码量 / 依赖 / 迁移 / 学习成本）→ 唯一推荐 + 淘汰理由 → 先改文档再改代码。禁止"听一句别的框架好"就换、禁止边换边写。
