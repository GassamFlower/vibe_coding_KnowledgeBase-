# 阶段2：立项

目标：产出 PRD，让团队 / AI 对目标、边界和证据有共同依据。

交付物 `docs/a-立项文档.md`（PRD 五段：背景目标 / 方案概述 / 具体方案 / 上线计划 / 附录），覆盖 10 项：
1. 项目立项说明：是什么 / 面向谁 / 解决什么问题 / 为什么值得做 / 第一版核心目标
2. 用户证据：至少 3 条真实证据（访谈原话 / 真实行为 / 竞品数据）+ 来源类型 + 证据强度
3. 项目核心功能和边界：第一版做什么、不做什么
4. Out-of-Scope：明确不做的事项 + 原因 + 重新评估时间
5. 产品流程和用户路径
6. 数据和业务对象
7. 技术路线初步判断
8. 风险清单：需求 / 技术 / 合规 / 上线
9. 后期规划和里程碑
10. 验收规则：可检查的标准

配套：`docs/b-功能清单.md`（按角色 / 业务流程 / 模块三个维度）、`docs/c-阶段计划.md`（第一阶段是 MVP）。

提示：朋友的夸奖、假设性回答不计入用户证据。Out-of-Scope 不写，第一版范围会无限扩大。
完成后 `state` 仍为 1（纯想法雏形），直到通过立项门才进入开发。
