# 业务门自动验收

> 基于 `../../templates/门禁卡-业务门.md` 转化的可执行评估项。
> 每项：检查什么 → 怎么检查 → 通过标准 → 证据要求。
> 智能体调用本文件，逐项收集证据并判定通过/不通过。

---

## 过门禁标准（硬指标）

### 指标 1：所有 P0 功能已开发完成

- **检查什么**：功能清单中 P0 项是否全部实现
- **怎么检查**：对照功能清单逐项核对实现 + 验收记录
- **通过标准**：P0 全部完成，每轮开发都有验收证据
- **证据要求**：功能清单路径 + 各模块验收记录

### 指标 2：每个模块走过测试六步法

- **检查什么**：`testing-strategy` Skill 是否每模块走完
- **怎么检查**：读取测试记录，检查 手动闭环 / 三类用例 / 回归自动化 / 假测试陷阱 / 安全攻防 / 防过度测试
- **通过标准**：无假测试、无过度测试，覆盖成功 / 失败 / 边界
- **证据要求**：测试记录路径

### 指标 3：安全审查 5 道关卡全过

- **检查什么**：身份认证 / 权限控制 / 输入校验 / 数据归属 / 注入防护
- **怎么检查**：读取安全审查报告 + 系统权限设计表
- **通过标准**：5 关全过，水平越权测试通过，无字符串拼接用户输入（用 ORM / 参数化）
- **证据要求**：安全审查报告路径 + 权限设计表

### 指标 4：安全审查报告已落盘 + 已 Git 提交

- **检查什么**：安全审查报告文件 + Git 提交历史
- **怎么检查**：读取报告 + `git log --oneline`
- **通过标准**：报告落盘，已提交
- **证据要求**：报告路径 + git log 输出

---

## 自动验收流程

```
1. 智能体读取本文件的 4 项硬指标
2. 逐项检查（功能清单 + 测试记录 + 安全报告 + Git 历史）
3. 每项收集证据：文件路径 / 命令输出
4. 生成验收报告（格式同立项门）
5. 全部通过 → 推进状态到上线门
6. 有未通过 → 列出整改清单，不推进状态
```

---

## 常见遗漏项（反模式检查）

- ⚠️ 一口气写完所有业务（必须拆轮）
- ⚠️ 跳过每轮验收
- ⚠️ 改了规则不改真源文档
- ⚠️ 一个模块未验收就开下一个
- ⚠️ 安全只做"要不要登录"忽略水平越权
- ⚠️ 让 AI 自己写过滤规则代替参数化查询
- ⚠️ 整改时顺手改其他代码
- ⚠️ 安全审查不给证据
