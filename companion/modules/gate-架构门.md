# 架构门自动验收

> 对照 `../../templates/门禁卡-架构门.md` 逐项收集证据并判定通过/不通过。

---

## 过门禁标准（11 项必须满足的指标）

1. **实施真源文档**：`docs/f-实施真源文档-第N阶段.md` 已写入大阶段 → 子阶段 → 步骤 + 每步验收标准；只写首个大阶段。
2. **前端能启动**：启动命令有输出，首页能打开，路由能跑通。证据：启动输出 + 页面截图或 URL。
3. **设计规范**：`docs/g-前端架构实施文档.md` 含风格方向 + 参考案例、token（颜色 / 字号 / 间距 / 圆角 / 阴影 / 断点）及文件位置、组件库与二次封装、响应式、页面状态（加载 / 空 / 错误 / 禁用 / 成功）、可访问性、AI 只用 token 的规则。
4. **API 接口清单**：`docs/i-API接口清单.md` 前后端共用，含路径 / 方法 / 调用方 / 权限 / 入参出参字段与示例 / 错误码 / 分页与排序白名单 / 幂等方案 / 角色 × 接口权限矩阵。
5. **数据库可用**：能连接、能建表、能插入查询测试数据。证据：schema.sql 路径 + 查询输出。
6. **数据库运行期设计**：索引清单（名称 / 字段顺序 / 对应查询 / 预估收益）、事务边界与隔离级别、migration 前进与回退、连接池参数、数据隔离、备份与恢复。
7. **后端四条线**：启动 / 接口 / 业务 / 运维都跑通。证据：启动输出 + 健康检查响应 + 日志样本。
8. **前后端联调**：跨域正确、响应格式一致，错误场景覆盖参数错误 / 未登录 / 无权限 / 资源不存在 / 系统异常。
9. **环境样例与文档**：`.env.example` 列出全部变量且不含真值；README 含依赖安装 / 启动 / 构建 / 测试 / 迁移命令；健康检查可访问。
10. **后端真源文档**：`docs/k-后端架构实施真源文档.md` 写实际实现，Agent 宪法已加引用条款。
11. **Git 提交 ≥6 次**：覆盖真源文档 / 前端骨架 / 数据库 / 后端骨架 / 联调 / 后端验收。

---

## 自动验收流程

1. 逐项检查文件、启动输出、数据库查询、Git 历史。
2. 每项收集证据：路径 / 行号 / 命令输出 / 截图。
3. 生成验收报告，每项标注 ✅ / ❌ + 证据或整改建议。
4. 全部通过 → 推进到业务门；有未通过 → 列整改清单，不推进状态。

---

## 常见遗漏项（反模式检查）

- ⚠️ 跳过实施真源文档直接写代码
- ⚠️ 一次性写完全部阶段
- ⚠️ 设计 token 没定就写页面，页面直接写十六进制颜色
- ⚠️ 只做正常状态，加载 / 空 / 错误 / 禁用状态缺失
- ⚠️ 接口清单前后端各写一份，字段和错误码对不上
- ⚠️ 列表接口没有条数上限，排序字段直接拼进 SQL
- ⚠️ 写操作没有幂等方案
- ⚠️ 直接连数据库建表（必须先出 schema.sql）
- ⚠️ 金额用 float，密码明文存储
- ⚠️ 建了表没写索引，多表写入没有事务边界
- ⚠️ migration 只写前进不写回退
- ⚠️ `.env.example` 缺失，README 没写启动命令，没有健康检查
- ⚠️ 只验后端不验前端，前端只看代码不打开浏览器
- ⚠️ 真源文档写设计意图不写实际实现

## 验收结果处理

### 全部通过

### 有未通过项

1. 生成整改清单（未通过指标 + 原因 + 整改建议）。
2. 不推进状态，整改后重新执行本验收。
3. 直到全部通过才推进状态。
