# Skill: database-design（数据库设计）

## 何时使用

- 用户说"帮我设计数据库""建几张表""这个功能需要什么表"；
- 前端骨架跑通，准备进入数据库阶段；
- 已有数据库结构混乱，需要重新梳理。

## 解决什么问题

防止 AI 上来就建表。先把业务对象、关系、范式、字段规范定清楚，再生成设计文件，最后才建表。

## 执行流程

1. **从前端反推数据**（前端已有时优先用这步）：
   - 列表 → 映射数据字段
   - 详情页 → 推导完整结构
   - 表单 → 定义提交数据
   - 按钮 → 确定操作行为
   - 状态 → 指明数据流转
2. **从业务流程找对象**：让 AI 列出项目核心业务对象（用户、订单、商品、文章、权限、日志等），先不建表。
3. **确认对象关系**：让 AI 解释每张表代表什么、哪些表关联、1:1 / 1:N / N:N、关联字段放哪张表、为什么这样设计。
4. **选数据库服务**：让 AI 给唯一推荐（普通业务优先 MySQL/PostgreSQL；Redis 仅在确有缓存/队列/高并发需求时引入）。
5. **按三大范式设计表结构**：
   - 第一范式：字段原子化
   - 第二范式：字段围绕当前表主对象
   - 第三范式：字段之间不互相依赖
   - 反范式必须有业务原因并说明
6. **规范常见字段**：
   - `id` / `created_at` / `updated_at` 自动维护
   - 不能物理删除的数据加 `deleted_at` 软删除
   - 密码用 `password_hash`，禁止明文
   - 金额用整数（分）或精确数字类型，说清货币和精度
   - 状态字段定义枚举值
   - 字段名用英文下划线
7. **先生成设计文件再建表**：
   - 生成 `schema.sql` 或 migration 文件
   - 核对业务对象、表关系、字段、三大范式
   - 确认后再执行建表
   - 后续变更也先改 schema/migration 再执行
8. **写进实施计划**：业务对象 / 关系 / 主数据库 / 是否 Redis / 核心表 / 字段规范 / 唯一性 / 关联 / 软删除策略 / 范式校验 / 验收标准。
9. **跑通基础结构**：能连接 / 能建表 / 能 migration / 能插入和查询测试数据。
10. **触发 Git 提交**：把设计文件和基础结构作为一次稳定提交。

## 运行期设计补充

基础表结构确定后，继续检查以下内容。这些内容决定数据库上线后是否稳定，不能留到出问题再补。

### 索引

- 先列真实查询，再设计索引：列表筛选、详情页关联、后台搜索、排序字段；
- 每个索引写清服务哪个查询，没有查询支撑的索引不加；
- 联合索引注意字段顺序，把选择性高的字段放在前面；
- 不在低选择性字段上单独建索引；
- 写入频繁的表控制索引数量；
- 上线前用真实数据量检查关键查询的执行计划。

### 事务

- 多张表一起变动时必须使用事务；
- 事务边界覆盖完整的业务动作，不在事务中执行网络请求；
- 失败时整体回滚，不允许一半成功一半失败；
- 支付、订单、库存、退款等关键流程必须有事务或等价的补偿机制；
- 事务隔离级别按业务需要选择，不默认使用最高级别。

### 迁移

- 所有结构变更先写 migration，再执行；
- migration 文件入库，按顺序执行，不手工修改生产表结构；
- 区分可逆迁移和不可逆迁移；
- 不可逆迁移先备份，并写清恢复步骤；
- 大表变更评估锁表时间，必要时分步执行；
- 上线前在预发环境执行一次完整迁移。

### 连接与容量

- 设置连接池上限，按数据库允许的连接数分配；
- 设置连接超时、查询超时和空闲回收；
- 不在请求中临时创建大量连接；
- 评估当前用户量下的连接数和慢查询数量；
- 关键表设置合理的保留和归档策略。

### 数据隔离与权限

- 多租户或按用户隔离的数据，查询必须带租户或用户条件；
- 需要数据库层兜底时，配置行级权限；
- 应用层权限检查不能省略；
- 数据库账号按最小权限分配，应用账号不拥有管理权限；
- 备份文件和导出文件按敏感数据处理。

### 备份与恢复

- 明确备份频率、保留时间和存放位置；
- 至少验证一次恢复流程，不只验证备份文件存在；
- 关键操作前手动备份；
- 备份文件加密，访问权限受控；
- 写清恢复步骤和负责人。

## 输出

- 数据库设计文件（`schema.sql` 或 migration）；
- 索引清单与对应查询；
- 事务边界说明；
- 迁移计划和回滚步骤；
- 连接池与容量说明；
- 备份与恢复步骤；
- 数据库实施计划；
- 已通过的 Git 提交。

## 约束

- ❌ 不直接连数据库建表，跳过设计文件；
- ❌ 不把所有数据塞进一个大字段；
- ❌ 不在表关系没想清楚时开建；
- ❌ 不明文存储密码；
- ❌ 不用浮点数存金额；
- ❌ 不在没有 migration 记录的情况下手动改字段；
- ❌ 不在不说明原因的情况下做反范式设计；
- ❌ 不建没有查询支撑的索引；
- ❌ 不在多表变动时跳过事务；
- ❌ 不在没有备份和恢复步骤时执行不可逆迁移；
- ❌ 不让应用账号拥有数据库管理权限。
