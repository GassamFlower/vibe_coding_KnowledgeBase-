# Skill: api-design（接口设计）

## 何时使用

- 架构门，准备搭后端骨架；
- 前后端联调之前，需要先定接口规范；
- 用户说“帮我设计接口”“接口怎么分”“列表怎么分页”；
- 接口越来越多，前端记不住，改一个字段就影响多个页面；
- 涉及批量操作、文件上传、支付回调、实时更新。

## 解决什么问题

防止接口停在“能跑”的层面。接口没有命名、分页、错误码和权限规则，前端会反复猜测，联调会反复返工。本 Skill 把接口从“一个地址”变成“一份可核对的规范”。

## 执行流程

### 第 1 步：列出资源与动作

先写资源清单，再写接口。资源使用名词复数，路径中不使用动词。

示例：

- `GET /api/movies` 获取电影列表；
- `GET /api/movies/{id}` 获取电影详情；
- `POST /api/movies` 创建电影；
- `PATCH /api/movies/{id}` 修改电影；
- `DELETE /api/movies/{id}` 删除电影。

规则：

- 路径使用小写和中划线；
- 不使用 `getMovies`、`createMovie` 这类动词路径；
- 动作确实无法用资源表达时，使用明确的子资源，例如 `POST /api/orders/{id}/cancel`。

### 第 2 步：判断嵌套与扁平

判断标准：前端拿到响应后，是否还需要再发请求才能渲染页面。

| 场景 | 推荐结构 | 原因 |
|---|---|---|
| 详情页 | 嵌套 | 一次返回关联信息，减少网络往返 |
| 列表页 | 扁平或轻度嵌套 | 只返回列表需要的字段，减少响应体积 |
| 管理后台表格 | 扁平 | 先显示关键字段，点击后再加载详情 |
| 搜索结果 | 扁平加少量嵌套 | 只带展示需要的关联字段 |

嵌套不是越多越好。关联数据很大时，分成单独接口。

### 第 3 步：定义分页、筛选和排序

- 列表接口必须分页，不允许无上限返回全部记录；
- 默认每页 20 条，设置最大上限；
- 页码分页适合后台表格，游标分页适合信息流和大数据量；
- 筛选参数使用明确名称，例如 `status`、`tag`、`keyword`；
- 排序参数使用白名单，例如 `sort=created_at&order=desc`，不允许前端传任意字段；
- 响应中返回总数或下一页游标，前端不需要猜测。

### 第 4 步：统一响应结构

成功响应和失败响应使用同一套外层结构，例如：

```json
{
  "data": {},
  "error": null,
  "requestId": "req_123"
}
```

失败响应：

```json
{
  "data": null,
  "error": {
    "code": "ORDER_NOT_FOUND",
    "message": "订单不存在"
  },
  "requestId": "req_123"
}
```

规则：

- 业务错误使用稳定的机器可读错误码；
- 错误信息给人看，错误码给程序看；
- 生产环境不返回调用信息、数据库表名和文件路径；
- 每个响应带请求标识，方便日志排查。

### 第 5 步：输入校验与权限

- 后端使用 schema 校验所有输入，不信任前端传来的任何字段；
- 校验范围包括类型、长度、范围、枚举、必填、格式；
- 每个接口写清是否需要登录、需要什么角色、是否检查数据归属；
- 对象级权限必须检查，例如用户只能修改自己的订单；
- 不允许把权限判断只放在前端页面。

### 第 6 步：处理幂等与重试

以下场景必须考虑幂等：

- 创建订单、支付、退款；
- 第三方回调；
- 网络超时后的重试；
- 用户连续点击提交按钮。

做法：

- 客户端生成幂等键，服务端记录并拒绝重复请求；
- 或者使用业务唯一键，例如订单号；
- 返回第一次请求的结果，不重复创建数据；
- 记录重复请求日志。

### 第 7 步：批量、上传和实时更新

- 批量操作提供批量接口，避免前端循环调用几十次；
- 批量接口返回逐条结果，允许部分成功；
- 文件上传使用预签名地址或直传，限制类型和大小；
- 实时更新优先使用 SSE；需要双向通信时才使用 WebSocket；
- 没有明确需求时不引入实时通道。

### 第 8 步：写接口清单

每个接口至少记录：

| 字段 | 内容 |
|---|---|
| 路径与方法 | `/api/movies/{id}`，GET |
| 用途 | 获取电影详情 |
| 权限 | 需要登录，普通用户 |
| 入参 | 路径参数、查询参数、请求体 |
| 出参 | 成功响应示例 |
| 错误码 | 可能出现的业务错误 |
| 分页 | 是否分页、默认值、上限 |
| 幂等 | 是否幂等、幂等键 |
| 变更记录 | 字段新增、废弃、版本 |

## 输出

- 接口清单；
- 统一响应结构与错误码表；
- 成功、失败、边界请求示例；
- 权限表和幂等说明；
- 前端调用说明。

## 约束

- ❌ 不在路径中使用动词；
- ❌ 不用 200 状态码包装所有错误；
- ❌ 不返回无上限列表；
- ❌ 不把前端校验当成唯一校验；
- ❌ 不在生产错误信息里返回调用信息和数据库细节；
- ❌ 不对支付、订单、回调等关键写操作忽略幂等；
- ❌ 不随意改字段名；确需修改时先加新字段，再迁移，再废弃旧字段。
