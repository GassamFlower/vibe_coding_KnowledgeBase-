# 架构门自动验收

> 基于 `../../templates/门禁卡-架构门.md` 转化的可执行评估项。
> 每项：检查什么 → 怎么检查 → 通过标准 → 证据要求。
> 智能体调用本文件，逐项收集证据并判定通过/不通过。

---

## 过门禁标准（11 项必须满足的指标）

### 指标 1：实施真源文档已分解（首个阶段）

- **检查什么**：`docs/f-实施真源文档-第N阶段.md` 是否已写入文件，大阶段→子阶段→步骤清晰
- **怎么检查**：读取文件，检查大阶段 / 子阶段 / 步骤 / 验收标准
- **通过标准**：首阶段已分解完、每步有验收标准、没一次性分解完所有阶段、临时想法写回真源文档
- **证据要求**：文件路径 + 章节结构

### 指标 2：前端能启动、首页能打开

- **检查什么**：前端项目能否启动，首页能否打开
- **怎么检查**：启动命令 + 浏览器 / 截图
- **通过标准**：能启动、首页能打开、路由能跑通
- **证据要求**：启动命令输出 + 首页截图 / URL

### 指标 3：设计规范已写入文件

- **检查什么**：`docs/g-前端架构实施文档.md` 是否包含完整设计规范
- **怎么检查**：读取文档，核对风格方向、token、组件库、响应式、页面状态、可访问性
- **通过标准**：
  - 风格方向：一句话方向 + 2-3 个参考案例
  - 设计 token：颜色 / 字号 / 间距 / 圆角 / 阴影 / 断点的具体值和文件位置
  - 组件库：选哪个、版本、哪些直接用、哪些二次封装
  - 响应式：断点值和每个断点下的布局变化
  - 页面状态：加载 / 空 / 错误 / 禁用 / 成功各有一个示例
  - 可访问性：键盘操作路径、对比度要求、语义标签规则
  - AI 规则：只允许使用 token，禁止直接写十六进制颜色和随手取的字号
- **参考库**：设计 token、组件、页面状态、响应式、无障碍与 AI 规则可对照 `references/UIUX参考库索引.md` 的阶段 6 入口（`DESIGN_SYSTEM.md` §1–§8、§10、§11、`projects.html`、`patterns.html`）
- **证据要求**：文件路径 + 各章节标题 + token 文件路径

### 指标 4：接口清单已写入文件

- **检查什么**：`docs/i-API接口清单.md` 是否存在，前后端是否共用同一份
- **怎么检查**：读取文件，核对路径 / 方法 / 权限 / 入参 / 出参 / 错误码 / 分页 / 幂等
- **通过标准**：
  - 资源划分和接口列表齐全
  - 每个接口有路径、方法、调用方、权限要求
  - 入参出参写明字段名、类型、必填、取值范围、示例
  - 错误场景和错误码齐全
  - 列表接口有分页参数、默认条数、最大条数、排序白名单
  - 写操作标了幂等方案
  - 角色 × 接口权限矩阵存在
- **证据要求**：文件路径 + 章节结构 + 接口数量

### 指标 5：数据库能连接、能建表、能插入查询

- **检查什么**：schema.sql 可执行 + 测试数据能插入查询
- **怎么检查**：执行 migration + 查询命令
- **通过标准**：库能连、表能建、能插入查询测试数据
- **证据要求**：schema.sql 路径 + 查询命令输出

### 指标 6：数据库迁移、索引、事务边界已说明

- **检查什么**：`docs/h-数据库设计文档.md` 是否写了运行期设计
- **怎么检查**：读取文档 + 检查索引证据
- **通过标准**：
  - 索引清单：索引名、字段顺序、对应查询、预估收益
  - 事务边界：多表写入场景的起止、隔离级别、失败回滚
  - 迁移：每条 migration 有前进和回退步骤，先备份再执行
  - 连接池：最大连接数、获取超时、空闲回收与数据库上限匹配
  - 数据隔离：查询带租户或用户标识
  - 备份：频率、保留天数、恢复步骤
- **证据要求**：文档路径 + `SHOW INDEX` 输出

### 指标 7：后端 4 条线跑通

- **检查什么**：启动线 / 接口线 / 业务线 / 运维线
- **怎么检查**：启动命令 + 健康检查 + 示例接口 + 日志
- **通过标准**：四条线都跑通
- **证据要求**：启动输出 + 健康检查响应 + 日志样本

### 指标 8：前后端联调验证通过

- **检查什么**：前端调通后端示例接口，跨域 / 响应格式 / 错误场景一致
- **怎么检查**：联调报告（请求命令 + 响应输出 + 是否通过）
- **通过标准**：联调报告完整，错误场景覆盖（参数错误 / 未登录 / 无权限 / 资源不存在 / 系统异常）
- **证据要求**：联调报告路径

### 指标 9：`.env.example`、README、健康检查已准备好

- **检查什么**：环境变量样例、启动文档、健康检查是否齐全
- **怎么检查**：读取 `.env.example` 和 README，请求健康检查接口
- **通过标准**：
  - `.env.example` 列出全部变量名和说明，不含真值
  - README 写清依赖安装、启动、构建、测试、迁移命令
  - 健康检查接口可以访问
- **证据要求**：文件路径 + 健康检查响应

### 指标 10：后端架构实施真源文档已写入文件

- **检查什么**：`docs/k-后端架构实施真源文档.md` 是否生成
- **怎么检查**：读取文件，检查目录责任 / 接口规则 / 错误处理 / 启动证据 / 框架复用边界 / 新增模块规则
- **通过标准**：真源文档已写入文件，写的是实际实现（非设计意图）；Agent 宪法已加引用条款
- **证据要求**：文件路径 + 章节标题；宪法引用位置

### 指标 11：已 Git 提交（至少 6 次）

- **检查什么**：Git 提交历史（真源文档分解 / 前端骨架 / 数据库 / 后端骨架 / 联调 / 后端验收）
- **怎么检查**：`git log --oneline`
- **通过标准**：至少 6 次提交
- **证据要求**：`git log` 输出

## 自动验收流程

```
1. 智能体读取本文件的 11 项必须满足的指标
2. 逐项检查（文件存在性 + 内容检查 + Git 历史）
3. 每项收集证据：
   - 文件路径
   - 关键内容行号
   - 命令输出（如 git log / 启动输出）
4. 生成验收报告：

   验收报告：架构门
   ================
   指标 1 实施真源文档：✅ 通过
     证据：docs/f-实施真源文档-第1阶段.md，大阶段/子阶段/步骤在第 3-40 行
   指标 2 前端启动：✅ 通过
     证据：npm run dev 输出，首页截图 index.png
   指标 3 设计规范：✅ 通过
     证据：docs/g-前端架构实施文档.md 第 4-30 行，token 在 src/styles/tokens.css
   ...
   指标 11 Git 提交：❌ 未通过
     原因：只有 5 次提交，缺少"后端验收"提交
     整改建议：git commit -m "chore: 架构验收通过，写入实施真源文档"

5. 全部通过 → 推进状态到业务门
6. 有未通过 → 列出整改清单，不推进状态
```

## 常见遗漏项（反模式检查）

智能体验收时，额外检查以下反模式：

- ⚠️ 跳过实施真源文档分解直接写代码
- ⚠️ 一次性分解完所有阶段（应该完成一个分解一个）
- ⚠️ 设计 token 没定就写页面
- ⚠️ 页面直接写十六进制颜色和随手取的字号（token 形同虚设）
- ⚠️ 只做正常状态，加载、空、错误、禁用状态全部缺失
- ⚠️ 只做桌面端，移动端打开就错位
- ⚠️ 接口清单前后端各写一份（字段和错误码对不上）
- ⚠️ 列表接口没有条数上限，排序字段直接拼进 SQL
- ⚠️ 写操作没有幂等方案，重复提交产生重复订单或重复扣款
- ⚠️ 直接连数据库建表（必须先出 schema.sql）
- ⚠️ 金额用 float（必须用 decimal）
- ⚠️ 密码明文存储
- ⚠️ 建了表没写索引，等数据变多才发现查询慢
- ⚠️ 多表写入没有事务边界说明
- ⚠️ migration 只写前进不写回退
- ⚠️ 后端骨架不基于架构设计文档
- ⚠️ 跳过后端联调直接写业务
- ⚠️ 4 条线没跑通就宣布完成
- ⚠️ `.env.example` 缺失，换一台机器起不来
- ⚠️ README 没写依赖安装、启动、构建、测试、迁移命令
- ⚠️ 没有健康检查接口，部署后无法判断服务是否活着
- ⚠️ 只验后端不验前端
- ⚠️ 前端只看代码不打开浏览器验证
- ⚠️ 验收不给证据，只说"已完成"
- ⚠️ 真源文档写设计意图不写实际实现
- ⚠️ 改了规则没同步真源文档
