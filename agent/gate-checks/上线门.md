# 上线门自动验收

> 基于 `../../templates/门禁卡-上线门.md` 转化的可执行评估项。
> 每项：检查什么 → 怎么检查 → 通过标准 → 证据要求。
> 智能体调用本文件，逐项收集证据并判定通过/不通过。

---

## 过门禁标准（7 项硬指标）

### 指标 1：5 维度审查完成，无 🔴 严重项

- **检查什么**：上线前总验收的 5 维度审查（结构 / 规则 / 安全 / 数据 / 可维护性）
- **怎么检查**：读取 `docs/p-上线前验收报告.md`，核对 5 维度逐项判断
- **通过标准**：5 维度每项给了"通过 / 风险 / 严重"判断 + 证据（文件 + 行号）；无 🔴 严重项
- **证据要求**：验收报告路径 + 5 维度结论

### 指标 2：🟡 风险项已登记后期清单

- **检查什么**：🟡 风险项是否登记到后期处理清单（可上线后修）
- **怎么检查**：检查报告中的 🟡 风险项清单是否完整、有后续跟进方式
- **通过标准**：🟡 风险项全部登记，无遗漏；🟢 建议项也已列明（可选优化）
- **证据要求**：风险项清单

### 指标 3：上线前验收报告已落盘

- **检查什么**：`docs/p-上线前验收报告.md` 是否存在
- **怎么检查**：读取文件，检查总体评估（go / no-go / conditional go）+ 整改清单
- **通过标准**：报告落盘、总体评估明确（不给"视情况而定"）、整改清单分级完整
- **证据要求**：文件路径 + 总体评估结论

### 指标 4：项目已上线

- **检查什么**：项目真实上线（环境变量 / 数据库迁移 / 域名 SSL / 观察清单）
- **怎么检查**：核对上线动作清单（部署记录 / 访问验证 / 观察清单）
- **通过标准**：上线动作全部完成、线上可访问（或部署到目标环境）、上线后观察清单已列（关键指标 / 告警阈值 / 回滚条件）
- **证据要求**：部署记录 + 线上访问验证输出 + 观察清单

### 指标 5：复盘报告已落盘

- **检查什么**：`docs/q-项目复盘报告.md` 是否存在（Keep / Change / Add / 踩坑 / 下次提醒）
- **怎么检查**：读取文件，检查复盘完整性
- **通过标准**：复盘报告落盘，包含踩坑清单 + 下次项目提醒
- **证据要求**：文件路径 + 章节标题

### 指标 6：至少反哺 1 条新经验到 Skill 库

- **检查什么**：本次项目踩的坑是否有新规则反哺到 `skills/`
- **怎么检查**：检查 `skills/` 是否有本次项目新增/修改的规则文件（git diff 可见）
- **通过标准**：至少 1 条可执行规则反哺（写"以后注意"不算）；反哺内容具体到改哪个 Skill 文件、加哪条规则
- **证据要求**：Skill 文件改动记录 + 新增规则原文

### 指标 7：已 Git 提交

- **检查什么**：Git 提交历史（上线 + 复盘 + 反哺）
- **怎么检查**：`git log --oneline`
- **通过标准**：至少含"上线""复盘/反哺"相关提交
- **证据要求**：`git log` 输出

## 自动验收流程

```
1. 智能体读取本文件的 7 项硬指标
2. 逐项检查（文件存在性 + 内容检查 + Git 历史）
3. 每项收集证据：
   - 文件路径
   - 关键内容行号
   - 命令输出（如 git log / 线上访问验证）
4. 生成验收报告：

   验收报告：上线门
   ================
   指标 1 5维度审查：✅ 通过
     证据：docs/p-上线前验收报告.md，5 维度结论在第 3-60 行，无 🔴
   指标 2 风险项登记：✅ 通过
     证据：🟡 风险项 3 条已登记，见报告第 61-70 行
   ...
   指标 6 Skill 反哺：❌ 未通过
     原因：踩坑清单有了，但没落到 skills/ 具体文件
     整改建议：把"XX 坑"写成一条规则加进 skills/xxx.md

5. 全部通过 → 项目收官，标记"已上线"
6. 有未通过 → 列出整改清单，不推进状态
```

---

## 常见遗漏项（反模式检查）

智能体验收时，额外检查以下反模式：

- ⚠️ 跳过总验收直接上线
- ⚠️ 🔴 严重项没修完就上线
- ⚠️ 上线完就结束，Skill 没迭代
- ⚠️ 反哺只写"以后注意"（要写具体规则）
- ⚠️ 不记录下次项目提醒
- ⚠️ 审查不给证据，只说"看起来没问题"
- ⚠️ 顺手重构审查范围外的代码
- ⚠️ 上线后没有观察清单（关键指标 / 告警 / 回滚）
- ⚠️ 用"基本完成""应该没问题"等模糊词
- ⚠️ 没有证据就标记"通过"

### 全部通过

1. 更新 `PROJECT_STATUS.agent.md`：
   - `current_gate` 改为 `无（已上线）`
   - `current_phase` 改为 `14`（已完成）
   - `current_state` 改为 `4`（健康）
   - 验收清单全部勾选 ✅
2. Git 提交：`git commit -m "chore: 通过上线门，项目收官"`
3. 提示用户：项目已上线收官，反哺的新规则已被知识库继承

### 有未通过项

1. 生成整改清单（每项：未通过指标 + 原因 + 整改建议）
2. 不推进状态（🔴 未修完不允许上线）
3. 智能体协助整改，整改后重新执行本验收流程
4. 直到全部通过才收官
