# 上线门自动验收

> 基于 `../../templates/门禁卡-上线门.md` 转化的可执行评估项。
> 每项：检查什么 → 怎么检查 → 通过标准 → 证据要求。
> 智能体调用本文件，逐项收集证据并判定通过/不通过。

---

## 过门禁标准（14 项必须满足的指标）

### 指标 1：5 维度审查完成，无 🔴 严重项

- **检查什么**：上线前总验收的 5 维度审查（结构 / 规则 / 安全 / 数据 / 可维护性）
- **怎么检查**：读取 `docs/p-上线前验收报告.md`，核对 5 维度逐项判断
- **通过标准**：5 维度每项给了"通过 / 风险 / 严重"判断 + 证据（文件 + 行号）；无 🔴 严重项
- **证据要求**：验收报告路径 + 5 维度结论

### 指标 2：🟡 风险项已登记后期清单

- **检查什么**：🟡 风险项是否登记到后期处理清单（可上线后修）
- **怎么检查**：检查报告中的 🟡 风险项清单是否完整、有后续跟进方式
- **通过标准**：🟡 风险项全部登记，无遗漏；🟢 建议项也已列明（可选优化）
- **证据要求**：风险项清单

### 指标 3：上线检查清单逐项完成

- **检查什么**：构建 / 环境变量 / 迁移 / 域名 / HTTPS / 冒烟 / 监控 / 回滚是否逐项完成
- **怎么检查**：读取 `docs/p-上线检查清单.md`，逐项核对完成状态和证据
- **通过标准**：
  - 生产构建成功，构建产物中不含开发调试配置
  - 环境变量与密钥已在生产环境配置，未写入代码或仓库
  - 数据库迁移在生产库执行并验证结果
  - 上线前已备份，恢复步骤实际演练过
  - 域名解析正确，HTTPS 证书有效并开启自动续期
  - 静态资源缓存与压缩已配置
  - 健康检查地址可以访问
- **证据要求**：清单文件路径 + 每项命令或截图

### 指标 4：生产环境冒烟测试通过

- **检查什么**：关键路径是否在线上真实执行过
- **怎么检查**：按核心用户流程实际走一遍，收集每步请求和响应
- **通过标准**：注册 / 登录 / 核心流程 / 支付或提交 / 查询结果全部跑通；未执行的项目标记"未执行"
- **证据要求**：每步请求 + 响应 + 是否通过

### 指标 5：监控与告警已配置，回滚步骤已实际演练

- **检查什么**：日志、监控、告警、回滚是否真实可用
- **怎么检查**：查询本次请求日志、打开监控面板、触发测试告警、执行一次回滚
- **通过标准**：
  - 应用日志能查到本次请求记录
  - 监控面板能看到流量、错误率、响应时间
  - 告警规则已配置，并有测试告警
  - 回滚步骤已实际演练，回滚后冒烟测试通过
- **证据要求**：日志片段 + 监控截图 + 告警记录 + 回滚演练记录

### 指标 6：SEO 基础项与分享卡片已完成

- **检查什么**：页面 title / description、canonical、sitemap、robots、Open Graph
- **怎么检查**：抓取页面源码和分享卡片预览
- **通过标准**：
  - 每个页面有独立的 title 和 description
  - canonical、sitemap、robots.txt 已配置
  - 分享卡片已配置并验证显示
- **证据要求**：页面源码片段 + 分享预览截图

### 指标 7：访问统计已接入，关键事件已记录

- **检查什么**：统计脚本和核心事件是否真的能记录
- **怎么检查**：触发一次核心动作，查看统计后台事件
- **通过标准**：访问统计已接入；注册 / 登录 / 下单 / 支付 / 提交等核心事件能在后台看到
- **证据要求**：事件记录截图 + 脚本加载位置

### 指标 8：隐私政策 / 用户协议 / 备案等合规项已确认

- **检查什么**：隐私政策、用户协议、备案是否覆盖实际业务
- **怎么检查**：读取页面内容和隐私政策，核对收集的数据与第三方服务
- **通过标准**：
  - 涉及用户数据或支付时，隐私政策和用户协议已发布
  - 隐私政策覆盖实际收集的数据和使用的第三方服务
  - 境内服务器站点已备案并展示备案号
- **证据要求**：页面链接 + 政策内容 + 备案号

### 指标 9：上线后 24 小时、7 天、30 天指标已记录

- **检查什么**：上线后的观察数据和基线对比
- **怎么检查**：读取 `docs/r-上线后30天迭代计划.md` 和观察记录
- **通过标准**：
  - 24 小时指标已记录（访问量 / 错误率 / 响应时间 / 核心转化）
  - 7 天指标已记录并与基线对比
  - 30 天指标已记录并完成复盘
  - 用户反馈入口可用，反馈已登记
  - 30 天迭代计划已建立
- **证据要求**：观察记录 + 指标对比 + 迭代计划路径

### 指标 10：上线前验收报告已写入文件

- **检查什么**：`docs/p-上线前验收报告.md` 是否存在
- **怎么检查**：读取文件，检查总体评估（go / no-go / conditional go）+ 整改清单
- **通过标准**：报告已写入文件、总体评估明确（不给"视情况而定"）、整改清单分级完整
- **证据要求**：文件路径 + 总体评估结论

### 指标 11：项目已上线

- **检查什么**：项目真实上线并可访问
- **怎么检查**：访问生产地址 + 核对发布记录
- **通过标准**：生产地址可访问；发布记录已填写（版本号 / 时间 / 操作人 / 变更内容 / 部署命令 / 回滚命令）
- **证据要求**：访问输出 + 发布记录

### 指标 12：复盘报告已写入文件

- **检查什么**：`docs/q-项目复盘报告.md` 是否存在（上线记录 / 指标基线 / 踩坑 / Skill / Prompt / 下次提醒）
- **怎么检查**：读取文件，检查复盘完整性
- **通过标准**：复盘报告已写入文件，包含上线记录 + 指标基线 + 踩坑清单 + 下次项目提醒
- **证据要求**：文件路径 + 章节标题

### 指标 13：至少反哺 1 条新经验到 Skill 库

- **检查什么**：本次项目踩的坑是否有新规则反哺到 `skills/`
- **怎么检查**：检查 `skills/` 是否有本次项目新增/修改的规则文件（git diff 可见）
- **通过标准**：至少 1 条可执行规则反哺（写"以后注意"不算）；反哺内容具体到改哪个 Skill 文件、加哪条规则
- **证据要求**：Skill 文件改动记录 + 新增规则原文

### 指标 14：已 Git 提交

- **检查什么**：Git 提交历史（上线 + 复盘 + 反哺）
- **怎么检查**：`git log --oneline`
- **通过标准**：至少含"上线""复盘/反哺"相关提交
- **证据要求**：`git log` 输出

## 自动验收流程

```
1. 智能体读取本文件的 14 项必须满足的指标
2. 逐项检查（文件存在性 + 内容检查 + 线上验证 + Git 历史）
3. 每项收集证据：
   - 文件路径
   - 关键内容行号
   - 命令输出（如 git log / 线上访问验证 / 冒烟测试 / 回滚演练）
4. 生成验收报告：

   验收报告：上线门
   ================
   指标 1 5维度审查：✅ 通过
     证据：docs/p-上线前验收报告.md，5 维度结论在第 3-60 行，无 🔴
   指标 3 上线检查清单：✅ 通过
     证据：docs/p-上线检查清单.md 全部勾选，附构建与迁移输出
   指标 4 冒烟测试：✅ 通过
     证据：注册→登录→下单→支付→查询，每步响应见记录
   ...
   指标 13 Skill 反哺：❌ 未通过
     原因：踩坑清单有了，但没写进 skills/ 具体文件
     整改建议：把"XX 坑"写成一条规则加进 skills/xxx.md

5. 全部通过 → 项目收官，标记"已上线"
6. 有未通过 → 列出整改清单，不推进状态
```

## 常见遗漏项（反模式检查）

智能体验收时，额外检查以下反模式：

- ⚠️ 跳过总验收直接上线
- ⚠️ 🔴 严重项没修完就上线
- ⚠️ 生产环境没做冒烟测试（本地能跑就认为线上能跑）
- ⚠️ 环境变量和密钥写进代码，或打包进前端产物
- ⚠️ 数据库迁移只在本地跑过，生产没执行或执行失败
- ⚠️ 没有备份就开始迁移
- ⚠️ 域名解析或证书过期，上线后打不开
- ⚠️ 没有回滚方案，或回滚方案从未演练
- ⚠️ 没有监控和告警，服务挂了靠用户通知
- ⚠️ 日志里查不到请求，出问题无法定位
- ⚠️ 页面没有独立 title 和 description，分享出去是一串链接
- ⚠️ 统计脚本接入了但关键事件没记录，上线后无法判断效果
- ⚠️ 收集了用户数据却没有隐私政策，或隐私政策与实际收集不符
- ⚠️ 境内服务器没有备案
- ⚠️ 上线记录不写版本号和部署命令
- ⚠️ 上线后不看指标，不知道项目是否真的有用
- ⚠️ 上线完就结束，Skill 没迭代
- ⚠️ 反哺只写"以后注意"（要写具体规则）
- ⚠️ 不记录下次项目提醒
- ⚠️ 审查不给证据，只说"看起来没问题"
- ⚠️ 顺手重构审查范围外的代码
- ⚠️ 墓碑代码没清就上线（临时接口无权限校验 / 假数据进库是安全风险）
- ⚠️ 不列清单确认就直接删代码（或误删正式回归测试 / 运行日志）
- ⚠️ 用"基本完成""应该没问题"等模糊词
- ⚠️ 没有证据就标记"通过"

## 验收结果处理

### 全部通过

1. 更新 `PROJECT_STATUS.agent.md`：
   - `current_gate` 改为 `无（已上线）`
   - `current_phase` 改为 `14`（已完成）
   - `current_state` 改为 `4`（健康）
   - 验收清单全部勾选 ✅
2. Git 提交：`git commit -m "chore: 通过上线门，项目收官"`
3. 提示用户：项目已上线收官，30 天迭代计划进入执行，反哺的新规则已被知识库继承

### 有未通过项

1. 生成整改清单（每项：未通过指标 + 原因 + 整改建议）
2. 不推进状态（🔴 未修完不允许上线）
3. 智能体协助整改，整改后重新执行本验收流程
4. 直到全部通过才收官
