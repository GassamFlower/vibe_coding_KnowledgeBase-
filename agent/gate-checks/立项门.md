# 立项门自动验收

> 基于 `../../templates/门禁卡-立项门.md` 转化的可执行评估项。
> 每项：检查什么 → 怎么检查 → 通过标准 → 证据要求。
> 智能体调用本文件，逐项收集证据并判定通过/不通过。

---

## 过门禁标准（10 项必须满足的指标）

### 指标 1：立项文档已写入文件，采用 PRD 五段结构

- **检查什么**：`docs/a-立项文档.md` 是否存在，是否按 PRD 五段结构覆盖 10 项内容
- **怎么检查**：读取文件，检查五段结构和 10 个内容项是否齐全
- **通过标准**：
  - PRD 五段：背景目标 / 方案概述 / 具体方案 / 上线计划 / 附录
  - 10 项内容全部存在：
    1. 项目立项说明（是什么 / 面向谁 / 解决什么问题 / 为什么值得做 / 第一版核心目标）
    2. 用户证据（至少 3 条真实证据 + 来源类型 + 证据强度）
    3. 项目核心功能和边界（第一版做什么、不做什么）
    4. Out-of-Scope（明确不做 + 原因 + 重新评估时间）
    5. 产品流程和用户路径
    6. 数据和业务对象
    7. 技术路线初步判断
    8. 风险清单（需求 / 技术 / 合规 / 上线）
    9. 后期规划和里程碑
    10. 验收规则（可检查标准）
- **证据要求**：文件路径 + 五段结构章节标题 + 10 项内容对应段落

### 指标 2：至少 3 条真实用户证据

- **检查什么**：用户证据是否真实、足量、标注来源
- **怎么检查**：读取立项文档的用户证据章节，逐条核对来源类型和证据强度
- **通过标准**：
  - 至少 3 条真实用户证据（访谈原话 / 真实行为 / 竞品数据）
  - 每条标明来源类型和证据强度
  - 朋友夸奖、假设性回答、没有具体行为的描述已单独标出，未计入证据
- **证据要求**：证据条目 + 来源类型 + 强度标注

### 指标 3：Out-of-Scope 清单已写明

- **检查什么**：第一版边界是否明确，不做的事情是否写了原因和重新评估时间
- **怎么检查**：读取 Out-of-Scope 章节
- **通过标准**：
  - 第一版必须有 / 后续版本 / 明确不做三组已分开
  - 每条不做的事项写了原因
  - 写了重新评估时间或触发条件
- **证据要求**：三组范围清单 + 不做事项的原因与时间

### 指标 4：功能清单已分解（三维度）

- **检查什么**：功能清单是否按角色 / 业务流程 / 模块三维度分解
- **怎么检查**：读取功能清单，检查三个维度是否齐全
- **通过标准**：
  - 按角色分解（普通用户 / 管理员 / 商家等各自能做什么）
  - 按业务流程分解（核心流程走通）
  - 按模块分解（相关功能归到一起）
  - 每个功能写清：给谁用 / 输入 / 输出 / 权限 / 正常流程 / 异常边界
  - 复杂功能已单独建立文档（订单流转 / 支付退款 / 优惠叠加 / 权限系统）
  - 复杂功能在功能清单里留了索引
- **证据要求**：文件路径 + 三维度的章节标题 + 复杂功能索引

### 指标 5：阶段计划已制定（第一阶段是 MVP）

- **检查什么**：阶段计划是否存在，第一阶段是否是 MVP
- **怎么检查**：读取阶段计划，检查第一阶段描述
- **通过标准**：
  - 第一阶段是 MVP（能跑通核心流程的最小可用版本）
  - 每个阶段包含哪些功能已说明
  - 为什么这么排已说明
  - 只给大阶段划分，没细化到技术实现
- **证据要求**：文件路径 + 第一阶段描述

### 指标 6：技术选型文档已写入文件（唯一推荐）

- **检查什么**：选型文档是否存在，是否给了唯一推荐，运行环境是否可复现
- **怎么检查**：读取选型文档，检查"为什么不选其他方案"，检查 `.env.example` 与 README
- **通过标准**：
  - 产品形态已确定
  - 前端 / 后端 / 数据库 / SDK 已确定
  - 运行时与数据库版本已写明
  - 为什么选（结合项目情况）
  - 为什么不选其他方案（至少 3 个被淘汰方案）
  - 什么情况下需要重新评估
  - `.env.example` 写清每个变量填什么，不放真值
  - README 写清安装 / 启动 / 构建命令，按 README 能从零跑起来
- **证据要求**：文件路径 + 选型理由 + 不选理由 + 环境版本 + README 与 `.env.example`

### 指标 7：风险清单已列出

- **检查什么**：风险是否覆盖需求 / 技术 / 合规 / 上线四类
- **怎么检查**：读取风险清单章节，核对四类风险和应对策略
- **通过标准**：
  - 需求风险、技术风险、合规风险、上线风险都有条目
  - 每条风险写了影响和应对策略
- **证据要求**：风险条目 + 分类 + 应对策略

### 指标 8：架构设计文档已写入文件（7 项规则）

- **检查什么**：架构设计文档是否存在，包含 7 项核心规则
- **怎么检查**：读取文档，检查 7 个章节
- **通过标准**：7 项齐全
  1. 目录结构规则（每个目录职责 / 放什么 / 不放什么）
  2. 接口响应规则（统一格式 + 错误码表 + 分页规则）
  3. 错误处理规则（异常捕获 / 日志记录 / 返回格式）
  4. 日志规则（级别 / 格式 / 关键操作清单）
  5. 数据库连接规则（连接池 / 事务边界）
  6. 权限入口（认证中间件 / 角色校验 / 数据归属校验位置）
  7. 框架复用边界（必须用框架 / 可封装 / 禁止自造）
- **证据要求**：文件路径 + 7 个章节标题

### 指标 9：Agent 宪法已写入文件

- **检查什么**：宪法文件是否放在 IDE 会读取的位置
- **怎么检查**：检查以下任一文件是否存在
  - `AGENTS.md`（Codex）
  - `CLAUDE.md` 或 `.claude/CLAUDE.md`（Claude Code）
  - `.cursor/rules/`（Cursor）
  - `.trae/rules/project.md`（Trae）
- **通过标准**：
  - 宪法存在
  - 不超过 200 行
  - 含禁止事项（≥ 5 条）
  - 含验收标准
  - 含框架优先原则
  - 含成本 / 上下文约束（忽略目录、模型分层、会话熔断）
  - 各 IDE 入口文件已创建（只写引用，不复制内容）
- **证据要求**：文件路径 + 行数 + 禁止事项数量

### 指标 10：已 Git 提交（至少 4 次）且项目已建 .gitignore

- **检查什么**：Git 提交历史 + `.gitignore` 是否存在
- **怎么检查**：`git log --oneline` + `ls .gitignore`（或读取 `.gitignore` 内容）
- **通过标准**：
  - 至少 4 次提交（立项 / 选型 / 架构设计 / 宪法）
  - 项目根目录存在 `.gitignore`，且包含 node_modules / dist / .env / *.log 等核心忽略项
- **证据要求**：`git log` 输出 + `.gitignore` 文件内容

## 自动验收流程

```
1. 智能体读取本文件的 10 项必须满足的指标
2. 逐项检查（文件存在性 + 内容检查 + Git 历史）
3. 每项收集证据：
   - 文件路径
   - 关键内容行号
   - 命令输出（如 git log）
4. 生成验收报告：

   验收报告：立项门
   ================
   指标 1 立项文档：✅ 通过
     证据：docs/a-立项文档.md，PRD 五段 + 10 项在第 3-60 行
   指标 2 用户证据：✅ 通过
     证据：3 条证据在第 12-20 行，来源与强度已标注
   指标 3 Out-of-Scope：✅ 通过
     证据：第 24-31 行，含原因与重新评估时间
   指标 4 功能清单：✅ 通过
     证据：docs/b-功能清单.md，三维度在第 2/3/4 章
   ...
   指标 10 Git 提交：❌ 未通过
     原因：只有 3 次提交，缺少"宪法"提交
     整改建议：git commit -m "chore: 创建项目 Agent 宪法（基础版）"

5. 全部通过 → 推进状态到架构门
6. 有未通过 → 列出整改清单，不推进状态
```

## 常见遗漏项（反模式检查）

智能体验收时，额外检查以下反模式：

- ⚠️ 立项文档只在对话里聊过，没有写入文件
- ⚠️ 把朋友夸奖、假设性回答当成用户证据
- ⚠️ 只有"用户说想要"，没有真实行为、使用频率和代价
- ⚠️ PRD 里全是形容词，没有可验证的成功指标
- ⚠️ 没有 Out-of-Scope，第一版范围无限扩大
- ⚠️ 风险清单只写技术风险，漏了需求、合规和上线风险
- ⚠️ 跳过功能清单直接写代码
- ⚠️ 功能清单只按模块划分，漏了角色和业务流程维度
- ⚠️ 复杂功能硬塞进功能清单（应单独建立文档 + 留索引）
- ⚠️ 没做阶段计划就开始写代码
- ⚠️ 阶段计划直接细化到技术实现（选型没定就排细节 = 白排）
- ⚠️ 一份文档塞多件事（立项文档里混着技术选型 + 宪法）
- ⚠️ 文档之间没有引用关系
- ⚠️ MVP 边界没划清，第一版什么都想做
- ⚠️ 技术选型让 AI 列了 3 个方案让你选（必须给唯一推荐）
- ⚠️ 技术选型没写运行时版本和包管理器，换台机器跑不起来
- ⚠️ 只有代码没有 README 和 `.env.example`
- ⚠️ 宪法写了"建议""尽量"等软词（必须改成必须遵守的规则）
- ⚠️ 宪法超过 200 行（把细则移到真源文档）
- ⚠️ IDE 入口文件复制了宪法内容（应该只写引用）
- ⚠️ 宪法没写成本 / 上下文约束（忽略目录 + 模型分层 + 会话熔断）
- ⚠️ 项目没建 `.gitignore`，`.env` / node_modules 进了仓库
