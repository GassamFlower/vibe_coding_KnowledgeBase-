# 立项门自动验收

> 基于 `../../templates/门禁卡-立项门.md` 转化的可执行评估项。
> 每项：检查什么 → 怎么检查 → 通过标准 → 证据要求。
> 智能体调用本文件，逐项收集证据并判定通过/不通过。

---

## 过门禁标准（7 项硬指标）

### 指标 1：立项文档已落盘，覆盖 8 项内容

- **检查什么**：`docs/立项文档.md` 是否存在且覆盖 8 项内容
- **怎么检查**：读取文件，检查 8 个章节是否齐全
- **通过标准**：8 项内容全部存在
  1. 立项说明（项目是什么 / 面向谁 / 解决什么问题）
  2. 功能边界（第一版做什么、不做什么）
  3. 用户路径（产品流程）
  4. 业务对象清单（数据和对象）
  5. 技术路线初步判断
  6. 爆点差异（差异化亮点）
  7. 里程碑
  8. 验收规则（可检查标准）
- **证据要求**：文件路径 + 8 项内容的章节标题

### 指标 2：功能清单已拆解（三维度）

- **检查什么**：功能清单是否按角色 / 业务流程 / 模块三维度拆解
- **怎么检查**：读取功能清单，检查三个维度是否齐全
- **通过标准**：
  - 按角色拆解（普通用户 / 管理员 / 商家等各自能做什么）
  - 按业务流程拆解（核心流程走通）
  - 按模块拆解（相关功能归到一起）
  - 每个功能写清：给谁用 / 输入 / 输出 / 权限 / 正常流程 / 异常边界
  - 复杂功能已单独拆文档（订单流转 / 支付退款 / 优惠叠加 / 权限系统）
  - 复杂功能在功能清单里留了索引
- **证据要求**：文件路径 + 三维度的章节标题 + 复杂功能索引

### 指标 3：阶段计划已制定（第一阶段是 MVP）

- **检查什么**：阶段计划是否存在，第一阶段是否是 MVP
- **怎么检查**：读取阶段计划，检查第一阶段描述
- **通过标准**：
  - 第一阶段是 MVP（能跑通核心流程的最小可用版本）
  - 每个阶段包含哪些功能已说明
  - 为什么这么排已说明
  - 只给大阶段划分，没细化到技术实现
- **证据要求**：文件路径 + 第一阶段描述

### 指标 4：技术选型文档已落盘（唯一推荐）

- **检查什么**：选型文档是否存在，是否给了唯一推荐
- **怎么检查**：读取选型文档，检查"为什么不选其他方案"
- **通过标准**：
  - 产品形态已确定
  - 前端 / 后端 / 数据库 / SDK 已确定
  - 为什么选（结合项目情况）
  - 为什么不选其他方案（至少 3 个被淘汰方案）
  - 什么情况下需要重新评估
- **证据要求**：文件路径 + 选型理由 + 不选理由

### 指标 5：架构设计文档已落盘（7 项规则）

- **检查什么**：架构设计文档是否存在，包含 7 项核心规则
- **怎么检查**：读取文档，检查 7 个章节
- **通过标准**：7 项齐全
  1. 目录结构规则（每个目录职责 / 放什么 / 不放什么）
  2. 接口响应规则（统一格式 + 错误码表 + 分页规则）
  3. 错误处理规则（异常捕获 / 日志记录 / 返回格式）
  4. 日志规则（级别 / 格式 / 关键操作清单）
  5. 数据库连接规则（连接池 / 事务边界）
  6. 权限入口（认证中间件 / 角色校验 / 数据归属校验位置）
  7. 框架复用边界（必须用框架 / 可封装 / 禁止自造）
- **证据要求**：文件路径 + 7 个章节标题

### 指标 6：Agent 宪法已落盘

- **检查什么**：宪法文件是否放在 IDE 会读取的位置
- **怎么检查**：检查以下任一文件是否存在
  - `AGENTS.md`（Codex）
  - `CLAUDE.md` 或 `.claude/CLAUDE.md`（Claude Code）
  - `.cursor/rules/`（Cursor）
  - `.trae/rules/project.md`（Trae）
- **通过标准**：
  - 宪法存在
  - 不超过 200 行
  - 含禁止事项（≥ 5 条）
  - 含验收标准
  - 含框架优先原则
  - 各 IDE 入口文件已创建（只写引用，不复制内容）
- **证据要求**：文件路径 + 行数 + 禁止事项数量

### 指标 7：已 Git 提交（至少 4 次）

- **检查什么**：Git 提交历史
- **怎么检查**：`git log --oneline`
- **通过标准**：至少 4 次提交（立项 / 选型 / 架构设计 / 宪法）
- **证据要求**：`git log` 输出

## 自动验收流程

```
1. 智能体读取本文件的 7 项硬指标
2. 逐项检查（文件存在性 + 内容检查 + Git 历史）
3. 每项收集证据：
   - 文件路径
   - 关键内容行号
   - 命令输出（如 git log）
4. 生成验收报告：

   验收报告：立项门
   ================
   指标 1 立项文档：✅ 通过
     证据：docs/立项文档.md，8 项内容在第 3-45 行
   指标 2 功能清单：✅ 通过
     证据：docs/功能清单.md，三维度在第 2/3/4 章
   ...
   指标 7 Git 提交：❌ 未通过
     原因：只有 3 次提交，缺少"宪法"提交
     整改建议：git commit -m "chore: 创建项目 Agent 宪法（基础版）"

5. 全部通过 → 推进状态到架构门
6. 有未通过 → 列出整改清单，不推进状态
```

## 常见遗漏项（反模式检查）

智能体验收时，额外检查以下反模式：

- ⚠️ 立项文档只在对话里聊过没落盘
- ⚠️ 跳过功能清单直接写代码
- ⚠️ 功能清单只按模块拆，漏了角色和业务流程维度
- ⚠️ 复杂功能硬塞进功能清单（应单独拆文档 + 留索引）
- ⚠️ 没做阶段计划就开始写代码
- ⚠️ 阶段计划直接细化到技术实现（选型没定就排细节 = 白排）
- ⚠️ 一份文档塞多件事（立项文档里混着技术选型 + 宪法）
- ⚠️ 文档之间没有引用关系
- ⚠️ MVP 边界没划清，第一版什么都想做
- ⚠️ 技术选型让 AI 列了 3 个方案让你选（必须给唯一推荐）
- ⚠️ 宪法写了"建议""尽量"等软词（必须改成硬规则）
- ⚠️ 宪法超过 200 行（把细则移到真源文档）
- ⚠️ IDE 入口文件复制了宪法内容（应该只写引用）
