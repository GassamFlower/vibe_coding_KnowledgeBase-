# 上线门完整闭环

> 从"通过业务门"到"项目上线收官 + Skill 反哺"的完整执行流程。
> 输入：业务门已通过（current_gate=上线门，current_phase=13）
> 输出：通过上线门验收，项目收官，经验反哺知识库
> 适用状态：上线前（功能做完、安全过了，进入上线把关）

---

## 前置条件

- 项目已通过业务门：`PROJECT_STATUS.agent.md` 中 `current_gate=上线门`、`current_phase=13`
- 已有：全部业务模块 + 安全审查报告 + 联调报告 + API 接口清单
- 如果业务门未通过，先走 `../workflows/业务门闭环.md`

---

## 执行流程

### Step 0：衔接与定位

1. 读取 `PROJECT_STATUS.agent.md`，确认 `current_gate=上线门`、`current_phase=13`
2. 确认业务门产出齐全（P0 功能 / 安全审查报告）
3. 若不齐全，回到业务门闭环补齐，不进入上线门

---

### Step 1：上线前总验收（阶段 13）

**目标**：5 维度审查整个项目，本轮不改代码，只审查

#### 段 1 对话挖掘

智能体进入"代码审查员 + 上线把关人"角色。明确告诉用户：**本轮不改代码，只审查；不顺手重构审查范围外的代码**。

#### 段 2 整理成文

对整个项目做 5 维度审查：

1. 结构：目录放置 / 分层 / 重复实现
2. 规则：宪法 / 真源文档 / 框架规范是否被违反
3. 安全：输入校验 / 越权 / 密码 / 注入 / 过度防御
4. 数据：schema / 范式 / 敏感数据 / 软删除
5. 可维护性：命名 / 硬编码 / 提前封装 / 日志 / 错误 / 测试

每项给"通过 / 风险 / 严重"判断 + 证据（文件 + 行号）。

风险分级：
- 🔴 严重：阻断上线
- 🟡 风险：建议修，可上线后修
- 🟢 建议：可选优化

**调用子能力**：`requesting-code-review`（代码审查方法论）

#### 段 3 执行交付

- 无硬编码检查（配置 / URL / 密钥 / 错误信息）
- 无 TODO / FIXME 未处理
- 墓碑代码清理（临时测试 / 调试打印 / 临时测试接口 / 硬编码假数据 / 一次性脚本）：**先列清单发用户 → 用户确认 → 再删**；无权限校验的临时接口、硬编码假数据单独标出（安全风险）；正式回归测试与有意保留的运行日志不删
- 环境变量都从配置读
- 逐项填写 `docs/p-上线检查清单.md`：生产构建 / 环境变量 / 数据库迁移 / 备份与恢复 / 域名与 HTTPS / 静态资源缓存 / 健康检查
- SEO 基础项：每个页面独立的 title 和 description、canonical、sitemap、robots.txt、Open Graph 分享卡片
- 访问统计已接入，注册 / 登录 / 下单 / 支付 / 提交等核心事件能记录
- 合规项：隐私政策、用户协议、境内服务器备案号（按实际业务判断是否需要）
- 输出上线决策：总体评估 go / no-go / conditional go + 🔴 必改清单 + 🟡 可后修清单 + 🟢 建议清单 + 上线前必做动作

#### 段 4 验收固化

- 🔴 严重项必须修完（每项整改后重新验证）
- 生成 `docs/p-上线前验收报告.md`
- Git 提交：`git commit -m "chore: 完成上线前总验收"`

---

### Step 2：上线执行（阶段 14 前半）

**目标**：真实上线，线上可访问，出问题能回滚

#### 段 3 执行交付

按顺序执行，每步给命令 + 输出 + 是否通过：

1. 生产构建：给出构建命令和结果，确认产物不含开发调试配置
2. 环境变量：列出生产环境全部变量，确认已配置且未写入代码或仓库
3. 数据库迁移：在生产库执行，验证迁移后的表结构
4. 备份：执行备份，确认备份文件存在；恢复步骤实际演练过
5. 发布：给出发布命令和结果
6. 域名与证书：验证解析、HTTPS、证书有效期和自动续期
7. 冒烟测试：按核心用户流程实际走一遍（注册 / 登录 / 核心流程 / 支付或提交 / 查询结果），给出每步请求和响应
8. 日志与监控：确认日志能查到本次请求，监控面板有流量、错误率、响应时间
9. 告警：配置告警规则，触发一次测试告警
10. 回滚演练：实际执行一次回滚，回滚后再次冒烟测试并确认可用
11. 发布记录：版本号 / 时间 / 操作人 / 变更内容 / 部署命令 / 回滚命令

未执行的步骤标记"未执行"。不允许用"应该可以"代替实际执行。

#### 段 4 验收固化

- 记录部署证据（命令输出 / 线上访问验证 / 冒烟结果 / 回滚演练记录）
- Git 提交：`git commit -m "feat: 项目上线"`

---

### Step 3：上线后观察（阶段 14 中段）

**目标**：用真实数据判断上线效果，建立迭代节奏

#### 段 3 执行交付

- 24 小时指标：访问量 / 错误率 / 响应时间 / 核心转化
- 7 天指标：与基线对比
- 30 天指标：完成复盘
- 用户反馈入口可用，反馈逐条登记（来源 / 原话 / 场景 / 情绪）
- 建立 `docs/r-上线后30天迭代计划.md`：指标基线 / 反馈归类 / RICE 排序 / 本周假设 / 发布节奏与回退条件

#### 段 4 验收固化

- 指标与反馈记录写入文件
- Git 提交：`git commit -m "docs: 记录上线后观察数据与迭代计划"`

---

### Step 4：复盘 + Skill 反哺（阶段 14 后半）

**目标**：把本次项目经验反哺回知识库，让下个项目少踩坑

#### 段 1 对话挖掘

智能体进入"项目复盘员"角色，回顾：

1. 踩了哪些坑？（列具体场景 + 根因）
2. 哪些坑是现有 Skill / Prompt 没覆盖的？
3. 哪些 Skill 的规则需要强化或补充？
4. 下个项目开始前，应该更新哪些文档？

**关键**：反哺要写入具体规则（改哪个 Skill 文件、加哪条规则），写"以后注意"不算。

#### 段 4 验收固化

- 整理踩坑清单
- 至少 1 条新经验写入 `skills/`（新增规则 / 强化已有规则）
- 生成 `docs/q-项目复盘报告.md`（上线记录 / 指标基线 / Keep / Change / Add / 踩坑清单 / 下次提醒）
- Git 提交：`git commit -m "docs: 项目复盘 + Skill 反哺"`

---

### Step 5：上线门自动验收

智能体调用 `../gate-checks/上线门.md`，执行自动验收：

1. 逐项检查 14 项必须满足的指标（5 维度无 🔴 / 风险登记 / 上线检查清单 / 生产冒烟 / 监控告警与回滚演练 / SEO 与分享卡片 / 统计事件 / 合规项 / 24 小时与 7 天与 30 天指标 / 上线前验收报告 / 已上线与发布记录 / 复盘报告 / Skill 反哺 / Git）
2. 收集证据（文件路径 / 行号 / git log / 线上访问验证 / 冒烟输出 / 回滚演练记录 / 墓碑代码排查）
3. 检查反模式（常见遗漏清单）
4. 生成验收报告

#### 如果全部通过

1. 更新 `PROJECT_STATUS.agent.md`：
   - `current_gate` 改为 `无（已上线）`
   - `current_phase` 改为 `14`（已完成）
   - `current_state` 改为 `4`（健康）
   - 验收清单全部勾选 ✅
2. Git 提交：`git commit -m "chore: 通过上线门，项目收官"`
3. 提示用户：项目已上线收官，反哺的新规则已被知识库继承

#### 如果有未通过项

1. 生成整改清单（每项：未通过指标 + 原因 + 整改建议）
2. 不推进状态（🔴 未修完不允许上线）
3. 智能体协助整改，整改后重新执行本验收
4. 直到全部通过才收官

## 反模式（执行过程中避免）

- ❌ 跳过总验收直接上线
- ❌ 🔴 严重项没修完就上线
- ❌ 生产环境没做冒烟测试（本地能跑就认为线上能跑）
- ❌ 环境变量和密钥写进代码，或打包进前端产物
- ❌ 数据库迁移只在本地跑过，生产没执行或执行失败
- ❌ 没有备份就开始迁移
- ❌ 域名解析或证书过期，上线后打不开
- ❌ 没有回滚方案，或回滚方案从未演练
- ❌ 没有监控和告警，服务挂了靠用户通知
- ❌ 日志里查不到请求，出问题无法定位
- ❌ 页面没有独立 title 和 description，分享出去是一串链接
- ❌ 统计脚本接入了但关键事件没记录
- ❌ 收集了用户数据却没有隐私政策，或隐私政策与实际收集不符
- ❌ 境内服务器没有备案
- ❌ 上线完就结束，Skill 没迭代
- ❌ 反哺只写"以后注意"（要写具体规则）
- ❌ 不记录下次项目提醒
- ❌ 审查不给证据，只说"看起来没问题"
- ❌ 顺手重构审查范围外的代码
- ❌ 上线后没有观察清单（关键指标 / 告警 / 回滚）
- ❌ 验收用"基本完成"等模糊词
- ❌ 没有证据就标记"通过"
- ❌ 墓碑代码没清就上线（临时接口无权限校验 / 假数据进库是安全风险）
- ❌ 不列清单确认就直接删代码，或误删正式回归测试 / 运行日志
