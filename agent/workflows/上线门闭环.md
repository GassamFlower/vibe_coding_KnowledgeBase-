# 上线门完整闭环

> 从"通过业务门"到"项目上线收官 + Skill 反哺"的完整执行流程。
> 输入：业务门已通过（current_gate=上线门，current_phase=13）
> 输出：通过上线门验收，项目收官，经验反哺知识库
> 适用状态：上线前（功能做完、安全过了，进入上线把关）

---

## 前置条件

- 项目已通过业务门：`PROJECT_STATUS.agent.md` 中 `current_gate=上线门`、`current_phase=13`
- 已有：全部业务模块 + 安全审查报告 + 联调报告
- 如果业务门未通过，先走 `../workflows/业务门闭环.md`

---

## 执行流程

### Step 0：衔接与定位

1. 读取 `PROJECT_STATUS.agent.md`，确认 `current_gate=上线门`、`current_phase=13`
2. 确认业务门产出齐全（P0 功能 / 安全审查报告）
3. 若不齐全，回到业务门闭环补齐，不进入上线门

---

### Step 1：上线前总验收（阶段 13）

**目标**：5 维度审查整个项目，本轮不改代码，只审查

#### 段 1 对话挖掘

智能体进入"代码审查员 + 上线把关人"角色。明确告诉用户：**本轮不改代码，只审查；不顺手重构审查范围外的代码**。

#### 段 2 沉淀落地

对整个项目做 5 维度审查：

1. 结构：目录放置 / 分层 / 重复实现
2. 规则：宪法 / 真源文档 / 框架规范是否被违反
3. 安全：输入校验 / 越权 / 密码 / 注入 / 过度防御
4. 数据：schema / 范式 / 敏感数据 / 软删除
5. 可维护性：命名 / 硬编码 / 提前封装 / 日志 / 错误 / 测试

每项给"通过 / 风险 / 严重"判断 + 证据（文件 + 行号）。

风险分级：
- 🔴 严重：阻断上线
- 🟡 风险：建议修，可上线后修
- 🟢 建议：可选优化

**调用子能力**：`requesting-code-review`（代码审查方法论）

#### 段 3 执行交付

- 无硬编码检查（配置 / URL / 密钥 / 错误信息）
- 无 TODO / FIXME 未处理
- 无死代码
- 环境变量都从配置读
- 输出上线决策：总体评估 go / no-go / conditional go + 🔴 必改清单 + 🟡 可后修清单 + 🟢 建议清单 + 上线前必做动作

#### 段 4 验收固化

- 🔴 严重项必须修完（每项整改后重新验证）
- 生成 `docs/上线前验收报告.md` 落盘
- Git 提交：`git commit -m "chore: 完成上线前总验收"`

---

### Step 2：上线（阶段 14 前半）

**目标**：真实上线 + 上线后观察

#### 段 3 执行交付

1. 环境变量已配置
2. 数据库迁移已执行
3. 域名 / SSL 已配置（如需）
4. 上线后观察清单已列（关键指标 / 告警阈值 / 回滚条件）
5. 部署并验证线上可访问

#### 段 4 验收固化

- 记录部署证据（部署命令输出 / 线上访问验证）
- Git 提交：`git commit -m "feat: 项目上线"`

---

### Step 3：Skill 反哺（阶段 14 后半）

**目标**：把本次项目经验反哺回知识库，让下个项目少踩坑

#### 段 1 对话挖掘

智能体进入"项目复盘员"角色，回顾：

1. 踩了哪些坑？（列具体场景 + 根因）
2. 哪些坑是现有 Skill / Prompt 没覆盖的？
3. 哪些 Skill 的规则需要强化或补充？
4. 下个项目开始前，应该更新哪些文档？

**关键**：反哺要落到具体规则（改哪个 Skill 文件、加哪条规则），写"以后注意"不算。

#### 段 4 验收固化

- 整理踩坑清单
- 至少 1 条新经验写入 `skills/`（新增规则 / 强化已有规则）
- 生成 `docs/项目复盘.md`（Keep / Change / Add / 踩坑清单 / 下次提醒）
- Git 提交：`git commit -m "docs: 项目复盘 + Skill 反哺"`

---

### Step 4：上线门自动验收

智能体调用 `../gate-checks/上线门.md`，执行自动验收：

1. 逐项检查 7 项硬指标（5 维度无 🔴 / 风险登记 / 验收报告 / 已上线 / 复盘报告 / Skill 反哺 / Git）
2. 收集证据（文件路径 / 行号 / git log / 线上访问验证）
3. 检查反模式（10 项常见遗漏）
4. 生成验收报告

#### 如果全部通过

1. 更新 `PROJECT_STATUS.agent.md`：
   - `current_gate` 改为 `无（已上线）`
   - `current_phase` 改为 `14`（已完成）
   - `current_state` 改为 `4`（健康）
   - 验收清单全部勾选 ✅
2. Git 提交：`git commit -m "chore: 通过上线门，项目收官"`
3. 提示用户：项目已上线收官，反哺的新规则已被知识库继承

#### 如果有未通过项

1. 生成整改清单（每项：未通过指标 + 原因 + 整改建议）
2. 不推进状态（🔴 未修完不允许上线）
3. 智能体协助整改，整改后重新执行本验收
4. 直到全部通过才收官

---

## 完成判定

上线门闭环完成当：

- [ ] 5 维度审查完成，无 🔴 严重项
- [ ] 🟡 风险项已登记后期清单
- [ ] `docs/上线前验收报告.md` 已落盘
- [ ] 项目已上线（含观察清单）
- [ ] `docs/项目复盘.md` 已落盘
- [ ] 至少 1 条新经验反哺到 `skills/`
- [ ] PROJECT_STATUS 已更新（已上线 / 状态 4）
- [ ] 已 Git 提交"通过上线门"
- [ ] 智能体已提示用户项目收官

---

## 反模式（执行过程中避免）

- ❌ 跳过总验收直接上线
- ❌ 🔴 严重项没修完就上线
- ❌ 上线完就结束，Skill 没迭代
- ❌ 反哺只写"以后注意"（要写具体规则）
- ❌ 不记录下次项目提醒
- ❌ 审查不给证据，只说"看起来没问题"
- ❌ 顺手重构审查范围外的代码
- ❌ 上线后没有观察清单（关键指标 / 告警 / 回滚）
- ❌ 验收用"基本完成"等模糊词
- ❌ 没有证据就标记"通过"
