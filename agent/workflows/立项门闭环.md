# 立项门完整闭环

> 从"纯想法"到"通过立项门"的完整执行流程。
> 输入：项目想法
> 输出：通过立项门验收，进入架构门
> 适用状态：状态 0（纯想法，没代码没文档）

---

## 前置条件

- 项目处于状态 0（纯想法）：没代码没文档
- 如果有代码，先走 `../state-machine.md` 的状态判断决策树

---

## 执行流程

### Step 0：状态判断 + 初始化

1. 确认项目处于状态 0（没代码没文档）
2. 创建项目文件夹（英文 + 中划线，如 `task-manager`）
3. 复制 `../templates/PROJECT_STATUS.agent.md` 到项目根目录，重命名为 `PROJECT_STATUS.md`
4. 初始化 Git：`git init`
5. 更新 PROJECT_STATUS：
   - `project_name`：项目名
   - `start_date`：今天
   - `current_state`：0
   - `current_phase`：1
   - `current_gate`：立项门
   - `gate_entered_at`：今天

---

### Step 1：立项（阶段 1）

**目标**：把脑子里的想法变成立项文档 + 功能清单 + 阶段计划

#### 段 1 对话挖掘（用户主导）

智能体进入"产品合伙人"角色，明确告诉用户：**当前只做产品讨论，不写代码**。

智能体围绕以下问题深挖：
- 项目类型、目标用户、核心问题
- MVP 边界（第一版做什么、不做什么）
- 长期规划
- 主动指出盲区：权限、数据结构、状态字段、后期扩展、合规风险

智能体给**唯一推荐**，不列多方案。讨论清楚后，智能体说"现在可以写立项文档了"，等用户确认。

**调用子能力**：`brainstorming`

#### 段 2 沉淀落地（智能体起草 + 用户确认）

智能体生成 3 份文档（落盘到 `docs/`，按字母前缀命名，见操作手册 0.3）：

1. **`docs/a-立项文档.md`**（8 项内容）：
   - 立项说明 / 功能边界 / 用户路径 / 业务对象
   - 技术路线 / 爆点差异 / 里程碑 / 验收规则

2. **`docs/b-功能清单.md`**（三维度拆解）：
   - 按角色 / 按业务流程 / 按模块
   - 每个功能：给谁用 / 输入 / 输出 / 权限 / 正常流程 / 异常边界
   - 复杂功能单独拆文档 + 留索引

3. **`docs/c-阶段计划.md`**：
   - 第一阶段必须是 MVP（能跑通核心流程的最小可用版本）
   - 只给大阶段划分，不细化到技术实现

**调用子能力**：`project-breakdown` + `writing-plans`

用户 review，看不懂的地方让智能体用大白话讲。

#### 段 4 验收固化

- 更新 PROJECT_STATUS：勾选立项阶段完成
- Git 提交：`git commit -m "chore: 完成项目立项"`

---

### Step 2：技术选型（阶段 2）

**目标**：确定唯一推荐技术栈

#### 段 1 对话挖掘

智能体进入"架构顾问"角色。基于立项文档，给**唯一推荐技术栈**。

必须说明：
- 前端框架 + UI 组件库
- 后端语言 + 框架
- 数据库
- 为什么选它们（结合项目情况）
- 为什么不选其他常见方案（至少 3 个被淘汰方案）
- 什么情况下需要重新评估

画边界：必须遵守当前框架官方规范，优先选成熟框架和 SDK。

#### 段 2 沉淀落地

智能体生成选型文档，包含：
- 产品形态
- 前端 / 后端 / 数据库 / SDK 列表
- 选的理由
- 不选的理由
- 重评估条件

#### 段 4 验收固化

- Git 提交：`git commit -m "chore: 确定项目技术栈"`

---

### Step 3：架构设计文档（阶段 3）

**目标**：确定目录结构、接口规则、错误处理等架构规则

#### 段 1 对话挖掘

智能体输出架构设计文档**大纲**，用户确认大纲后再写完整版。

#### 段 2 沉淀落地

智能体生成架构设计文档，包含 7 项核心规则：
1. 目录结构规则（每个目录职责 / 放什么 / 不放什么）
2. 接口响应规则（统一格式 + 错误码表 + 分页规则）
3. 错误处理规则（异常捕获 / 日志记录 / 返回格式）
4. 日志规则（级别 / 格式 / 关键操作清单）
5. 数据库连接规则（连接池 / 事务边界 / ORM 使用规范）
6. 权限入口（认证中间件 / 角色校验 / 数据归属校验位置）
7. 框架复用边界（必须用框架 / 可封装 / 禁止自造）

写入 `docs/e-架构设计文档.md`。

#### 段 4 验收固化

- Git 提交：`git commit -m "chore: 完成架构设计文档"`

---

### Step 4：Agent 宪法（阶段 4）

**目标**：创建 Agent 宪法基础版，给 AI 立规矩

#### 段 1 对话挖掘

智能体进入"项目架构顾问"角色。基于立项 + 选型 + 架构设计，起草宪法大纲。

三条写作原则：
- **短**：不超过 200 行
- **硬**：每条都是必须遵守的硬规则
- **清楚**：每条能直接判断对错

只写长期原则，不写具体技术细节（细节放架构设计文档或真源文档）。

#### 段 2 沉淀落地

智能体生成 `AGENT_CONSTITUTION.md`，包含：
- 安全诚信条款
- 诚实边界条款
- 执行铁律
- 代码生成器承诺
- 项目专属条款（≥ 5 条，基于立项 + 选型 + 架构设计的真实情况）
- 禁止事项（≥ 5 条）
- 验收标准
- 框架优先原则

创建各 IDE 入口文件（**只写引用，不复制内容**）：
- Codex：`AGENTS.md`
- Cursor：`.cursor/rules/project.md`
- Claude Code：`CLAUDE.md`
- Trae：`.trae/rules/project.md`

入口文件内容示例：
```markdown
## 项目约束
本项目 Agent 必须遵守 AGENT_CONSTITUTION.md 中的所有规则。
请阅读 AGENT_CONSTITUTION.md 了解详细约束。
```

#### 段 4 验收固化

- Git 提交：`git commit -m "chore: 创建项目 Agent 宪法（基础版）"`

---

### Step 5：立项门自动验收

智能体调用 `../gate-checks/立项门.md`，执行自动验收：

1. 逐项检查 7 项硬指标
2. 收集证据（文件路径 / 行号 / Git log）
3. 检查反模式（12 项常见遗漏）
4. 生成验收报告

#### 如果全部通过

1. 更新 PROJECT_STATUS：
   - `current_gate` 改为 `架构门`
   - `current_phase` 改为 `5`
   - `gate_entered_at` 改为今天
   - 验收清单全部勾选 ✅
2. Git 提交：`git commit -m "chore: 通过立项门"`
3. 提示用户：可以进入架构门了，下一步是实施真源文档拆解

#### 如果有未通过项

1. 生成整改清单（每项：未通过指标 + 原因 + 整改建议）
2. 不推进状态
3. 智能体协助整改，整改后重新执行本验收
4. 直到全部通过才推进状态

---

## 完成判定

立项门闭环完成当：

- [ ] 7 项硬指标全部通过
- [ ] 反模式检查无遗漏
- [ ] PROJECT_STATUS 已更新（current_gate = 架构门）
- [ ] 已 Git 提交"通过立项门"
- [ ] 智能体已提示用户进入架构门

---

## 反模式（执行过程中避免）

- ❌ 跳过对话挖掘直接让智能体写文档
- ❌ 一口气做完 4 个阶段不验收
- ❌ 选型让智能体列多方案（必须唯一推荐）
- ❌ 宪法写"建议""尽量"等软词
- ❌ 宪法超过 200 行
- ❌ IDE 入口文件复制宪法内容
- ❌ 没过立项门就进入架构门
- ❌ 验收用"基本完成"等模糊词
- ❌ 没有证据就标记"通过"
