# 架构门完整闭环

> 从"通过立项门"到"通过架构门"的完整执行流程。
> 输入：立项门已通过（current_gate=架构门，current_phase=5）
> 输出：通过架构门验收，进入业务门
> 适用状态：开发中（立项门已通过，进入架构搭建）

---

## 前置条件

- 项目已通过立项门：`PROJECT_STATUS.agent.md` 中 `current_gate=架构门`、`current_phase=5`
- 已有：立项文档 / 功能清单 / 阶段计划 / 选型文档 / 架构设计文档 / Agent 宪法
- 如果立项门未通过，先走 `../workflows/立项门闭环.md`

---

## 执行流程

### Step 0：衔接与定位

1. 读取 `PROJECT_STATUS.agent.md`，确认 `current_gate=架构门`、`current_phase=5`
2. 确认已有立项门产出（立项 / 选型 / 架构设计 / 宪法）齐全
3. 若不齐全，回到立项门闭环补齐，不进入架构门

---

### Step 1：实施真源文档拆解（阶段 5）

**目标**：把首个大阶段拆成「大阶段 → 子阶段 → 步骤 + 验收标准」

#### 段 1 对话挖掘（用户主导）

智能体进入"实施规划师"角色。明确告诉用户：**本轮只拆首个大阶段，不拆全部**。

围绕以下问题深挖：
- 首个大阶段是什么（对应功能清单 / 阶段计划的哪个部分）
- 拆到什么粒度（子阶段 → 步骤 → 验收标准）
- 边界在哪（这阶段做什么、不做什么）

**调用子能力**：`writing-plans` + `project-breakdown`

#### 段 2 沉淀落地（智能体起草 + 用户确认）

智能体生成 `docs/f-实施真源文档-第N阶段.md`：
- 大阶段名称和目标
- 子阶段划分（每子阶段目标）
- 每子阶段步骤（每步做什么）
- 每步验收标准（怎么算做完）

#### 段 4 验收固化

- Git 提交：`git commit -m "chore: 完成首阶段实施真源文档拆解"`

---

### Step 2：前端骨架搭建（阶段 6）

**目标**：搭最小可运行前端骨架（能启动、首页能打开）

#### 段 1 对话挖掘

智能体进入"前端架构师"角色。确认设计风格 + UI 组件库 + 设计 token。

#### 段 2 沉淀落地

智能体生成 `docs/g-前端架构实施文档.md`（设计风格 / 技术方案 / UI 库 / 目录结构 / 模块边界 / 组件封装 / token / 多语言 / 主题 / 第一阶段内容 / 验收标准），并搭最小可运行骨架：
- 能启动、首页能打开
- 设计 token 已定义并生效
- UI 组件库已接入
- 路由结构搭好、接口层封装完成

**调用子能力**：`browser-verification`（验证首页能打开）

#### 段 4 验收固化

- Git 提交：`git commit -m "feat: 搭建前端最小可运行骨架"`

---

### Step 3：数据库设计（阶段 7）

**目标**：先出设计文件，再建表

#### 段 1 对话挖掘

智能体进入"数据库架构师"角色。从前端页面 + 业务对象清单反推数据，确认对象关系（ER 图）。

**调用子能力**：`database-design`

#### 段 2 沉淀落地

智能体生成 `docs/h-数据库设计文档.md` + `db/schema.sql`（业务对象清单 / 对象关系 / 主数据库 / 核心表 / 字段规范 / 表间关联 / 软删除 / 范式校验 / 验收标准）。

#### 段 3 执行交付

- 先生成设计文件，确认后再建表
- 数据库能连接、能建表、能插入查询测试数据

#### 段 4 验收固化

- Git 提交：`git commit -m "feat: 完成数据库设计文件并跑通基础结构"`

---

### Step 4：后端骨架搭建（阶段 8）

**目标**：基于架构设计文档搭最小可运行后端骨架，跑通四条线

#### 段 1 对话挖掘

智能体进入"后端架构师"角色。复核语言 / 框架，输出《后端架构实施计划》。

#### 段 2 沉淀落地

智能体生成 `docs/i-后端架构实施文档.md`（目录结构 / 接口响应 / 错误处理 / 日志 / 数据库连接 / 权限入口 / 框架复用边界 / 配置规范）。

#### 段 3 执行交付

搭最小可运行骨架（启动入口 / 环境变量 / 路由分组 / 健康检查 / 数据库连接 / 统一响应 / 统一错误 / 日志 / 参数校验 / 权限中间件占位），跑通四条线（启动 / 接口 / 业务 / 运维）。

**调用子能力**：`backend-architecture-acceptance`（提前介入骨架验收要点）

#### 段 4 验收固化

- Git 提交：`git commit -m "feat: 搭建后端最小可运行骨架，落盘后端架构实施文档"`

---

### Step 5：后端联调（阶段 9）

**目标**：验证前后端骨架是否接得上

#### 段 3 执行交付

智能体执行前后端联调验证：
1. 前端调用后端示例接口（健康检查），返回正常
2. 跨域配置正确
3. 响应格式前后端一致
4. 错误场景验证（参数错误 / 未登录 / 无权限 / 资源不存在 / 系统异常）
5. 网络 / 超时场景验证

每项给：请求命令 + 响应输出 + 是否通过。

#### 段 4 验收固化

- Git 提交：`git commit -m "chore: 前后端骨架联调验证通过"`

---

### Step 6：架构验收 + 架构门自动验收（阶段 10）

智能体调用 `../gate-checks/架构门.md`，执行自动验收：

1. 逐项检查 7 项硬指标（含前端浏览器验证、后端 9 项验收、联调报告、真源文档落盘、Git 提交）
2. 收集证据（文件路径 / 行号 / 启动输出 / git log / 截图）
3. 检查反模式（13 项常见遗漏）
4. 生成《后端架构实施真源文档》（`docs/k-后端架构实施真源文档.md`）《前端架构实施真源文档》（`docs/l-前端架构实施真源文档.md`）
5. Agent 宪法加引用条款（指向两份真源文档）
6. 生成验收报告

**调用子能力**：`backend-architecture-acceptance` + `browser-verification` + `requesting-code-review`

#### 如果全部通过

1. 更新 `PROJECT_STATUS.agent.md`：
   - `current_gate` 改为 `业务门`
   - `current_phase` 改为 `11`
   - `gate_entered_at` 改为今天
   - 验收清单全部勾选 ✅
2. Git 提交：`git commit -m "chore: 通过架构门"`
3. 提示用户：可以进入业务门了，下一步是业务模块开发

#### 如果有未通过项

1. 生成整改清单（每项：未通过指标 + 原因 + 整改建议）
2. 不推进状态
3. 智能体协助整改，整改后重新执行本验收
4. 直到全部通过才推进状态

---

## 完成判定

架构门闭环完成当：

- [ ] 7 项硬指标全部通过
- [ ] 反模式检查无遗漏
- [ ] 《后端架构实施真源文档》（`docs/k-`）《前端架构实施真源文档》（`docs/l-`）已落盘
- [ ] Agent 宪法已加引用条款
- [ ] PROJECT_STATUS 已更新（current_gate = 业务门）
- [ ] 已 Git 提交"通过架构门"
- [ ] 智能体已提示用户进入业务门

---

## 反模式（执行过程中避免）

- ❌ 跳过实施真源文档拆解直接写代码
- ❌ 一次性拆完所有阶段
- ❌ 设计 token 没定就写页面
- ❌ 直接连数据库建表（必须先出 schema.sql）
- ❌ 后端骨架不基于架构设计文档
- ❌ 跳过后端联调直接写业务
- ❌ 4 条线没跑通就宣布完成
- ❌ 只验后端不验前端
- ❌ 前端只看代码不打开浏览器验证
- ❌ 验收用"基本完成"等模糊词
- ❌ 没有证据就标记"通过"
- ❌ 没过架构门就进入业务门
