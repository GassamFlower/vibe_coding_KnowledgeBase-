# vibe coding之测试

测试两步走：

1. 手动验证，亲自跑通全链路功能流程；
2. AI增强，全量高压测试，捕捉隐蔽漏洞；

**第一步：手动测试-**&#x529F;能闭环

功能闭环：把项目中的每一个核心流程，完完整整的走一遍；

闭环走法：

1. 主流程走通，结果必须对；不能只看“点了有反应”（交互响应），要盯住的是“结果到底对不对”（逻辑准确）；
2. 歪路测试。专门走一遍非正常路径，看项目抗不抗的住。
3. 再回头点一遍牵连的功能点。

**第二步：功能测试**

一个功能要分3类情况来测：

1. 正常情况，该成功的要成功，结果要对；
2. 边界情况，那些最容易出现的临界点-就是刚好卡在边上的极端值（如：数量填0、负数、超大数等）
3. 异常情况，错误的、非法的请求要能被正确的拦在外面（如：没登陆就访问使用、非法字符注入、拿着别人身份来访问）

用AI来设计测试用例：

1. 正常且结果正确；
2. 边界值；
3. 异常与非法输入，正常情况下相关的计算结果和数据变化是不是正确的，不要只看接口有没有返回成功。

**第三步：把测试变成一张能反复跑的“自动回归网”**

回归测试：”请把我们前面确认的这些测试，做成可以用一条命令自动运行的方式，并告诉我这条命令是什么，跑完之后我怎么看结果，是通过还是失败。以后每次新增或修改功能都要重新运行全部测试，把通过和失败的结果发给我。“

**第四步：假测试陷阱**

验证测试真实性：”请检查我们当前的测试是不是真实有效的，请逐个说明：每个测试到底验证了什么业务结果，有没有真正调用被测的功能，然后请你故意在代码里制造一个错误，比如把某个金额故意算错再跑一遍对应的测试，确认它这时候会失败、会报红，如果代码都改错了，测试却还能通过，那就说明这个测试是无效的，加测试，必须重写。“

**第五步：安全攻防测试**

让AI扮演”专业攻击者“。身份设定：安全专家模式，任务：模拟供给视角 遍历接口漏洞。

代码审计：直接读取代码，从源头看哪儿写得有漏洞。

渗透测试：对接口发一堆恶意请求。

”请你现在不要扮演再开发者，而是扮演一名专业的测试和安全工程师，对我的后端接口做一次全方位的攻防测试，请分两步：先审查我的后端代码，从源头找出下面这些问题，再尽量写出可运行的脚本，真的对我的接口发起这些请求，实测抗不抗的住，请站在攻击者的角度，系统性的逐条尝试：一、数据越权，把请求里的订单号、用户ID改成别人的，看能不能查到改掉、删掉别人的数据；二、功能越权，用一个普通用户的身份，去调那些本该只有管理员才能用的接口，看拦不拦的住；3、身份认证，不登陆、或者伪造、篡改身份凭证去调用接口，看能不能蒙混过关；四、偷改字段提权，在提交的数据里偷偷多塞一个字段，比如把角色改为管理员、把价格改为0，把金额改为负数，看后端认不认；5、恶意输入与注入，在各个输入框里，构造精心设计的恶意内容，尝试SQL注入、命令注入、脚本注入；6、绕过前端限制，完全绕开页面，直接对接口发请求，看那些对前端的校验是不是形同虚设；七、敏感信息泄露，检查接口返回的内容里，有没有带出密码、密钥、别人的手机号之类的，这些本不该暴露的信息；八、资源滥用与防刷：对同一个接口（尤其是登录、发短信、下单）高频、超大并发地请求、看有没有限流、会不会被刷爆。请把发现的每一个问题，都列城一份清单内，逐条表ing：风险高低、会造成什么后果以及你是怎么复现的（发了什么请求返回了什么），**注意：先别动手改代码。**“

**第六步：别让AI测过头**

“请审查我们当前的测试，是不是存在过度测试，有没有为不重要的功能写了一大堆测试，有没有重复的或者没有意义的用例，请优先保证关键业务，也就是资金、权限、数据相关功能的测试深度，其余次要的帮我精简掉。”&#x20;
