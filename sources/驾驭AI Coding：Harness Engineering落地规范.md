## 前言

交付代码的成本已接近免费，但交付好代码的成本依然很高。Harness Engineering 把"好代码"的标准写进系统，让 AI 在约束下工作。

---

## 第一部分 理念与架构

### Harness Engineering 核心理念

**Agent = Model + Harness**

Harness 是指围绕模型构建的所有约束、工具和上下文管理系统。

### 6 大支柱

1. **上下文管理** - 控制输入给模型的信息质量和数量
2. **工具系统** - 定义 AI 可以调用的能力边界
3. **执行编排与多 Agent 协作** - 复杂任务的分解和协调
4. **状态与记忆** - 跨会话的上下文保持
5. **评估与观测** - 质量监控和反馈循环
6. **约束与恢复** - 错误处理和回滚机制

### AI Coding 一体化架构

```
输入层 → 工作台 → 底层支撑 → 输出层 → 度量层
```

- **输入层**: 需求、设计、规范
- **工作台**: IDE、Agent 环境
- **底层支撑**: 知识库、工具链、MCP
- **输出层**: 代码、测试、文档
- **度量层**: 质量指标、合规性检查

## 第二部分 落地实操

### 3 阶段实施路线图

#### 第一阶段：基础建设

1. **CodeBuddy 安装** - 团队统一的 AI 编码助手
2. **team-harness 仓库** - 集中管理 Harness 配置
3. **Rules** - 编码规范和约束规则
4. **AGENTS.md** - Agent 行为定义文件
5. **知识库** - 项目文档、最佳实践、案例库

#### 第二阶段：工具接入

1. **MCP (Model Context Protocol)** - 模型上下文协议
2. **Knot 平台** - 任务编排平台
3. **子智能体** - 专门化的 Agent 角色
4. **Skills** - 可复用的能力模块
5. **Plan 模式** - 任务规划和分解

#### 日常开发 SOP

- 需求分析 → Plan 模式生成任务清单
- 代码生成 → Rules 约束 + 知识库参考
- 代码审查 → harness-audit Skill 自动检查
- 测试验证 → 自动化测试 + 人工复核
- 文档同步 → 代码变更触发文档更新

#### 团队协作红线

- ❌ 禁止绕过 Rules 直接提交代码
- ❌ 禁止跳过自动化检查流程
- ❌ 禁止在缺乏上下文的情况下让 AI 生成关键代码
- ✅ 所有 AI 生成代码必须经过合规性检查
- ✅ 复杂任务必须使用 Plan 模式分解
- ✅ 保持 team-harness 仓库的及时更新

#### 常见问题与反模式

**反模式 1: 过度信任 AI**
- 问题: 直接采纳 AI 输出，缺乏审查
- 解决: 建立多层检查机制

**反模式 2: 上下文污染**
- 问题: 累积过多无关信息
- 解决: 定期清理上下文，保持专注

**反模式 3: 工具滥用**
- 问题: 使用不合适的工具完成任务
- 解决: 明确工具边界，按场景选择

#### harness-audit Skill 合规性自检示例

```yaml
检查项:
  - 代码风格符合 Rules 定义
  - 所有公开接口有文档注释
  - 测试覆盖率达标
  - 无安全漏洞模式
  - 依赖版本在允许范围内
```

## 第三部分 总结

从"人驱动 AI"到"AI 自驱动"的转变，流水的工具，铁打的规范。

**关键要点**:
- Harness Engineering 不是限制 AI，而是让 AI 在正确的轨道上运行
- 规范是团队协作的基础，也是 AI 可靠输出的保障
- 持续优化 Harness，让 AI 成为真正的团队成员
